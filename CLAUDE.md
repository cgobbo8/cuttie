# Cuttie

Outil d'extraction automatique des moments forts de VODs Twitch. URL in -> clips horizontaux analyses et scores out. Editeur de clips integre avec export Remotion.

Tourne 100 % en local (cible : app desktop Windows pour un ami streamer) : pas de Docker, Redis ni S3/MinIO. L'API et le worker partagent un dossier de donnees (`CUTTIE_DATA_DIR`) et se parlent en HTTP sur 127.0.0.1.

## Stack

- **API** : AdonisJS 7 (TypeScript), SQLite (better-sqlite3), Transmit SSE en memoire
- **Worker** : Python 3.12, serveur FastAPI local (file de jobs en memoire), SQLite (WAL), uv
- **Frontend** : React 19, TypeScript 5.9, Tailwind CSS 4, Vite 8, React Router 7
- **Editor** : Remotion 4 (player + renderer), canvas editor custom
- **ML/Audio** : librosa (11025 Hz), PANNs CNN14 (AudioSet) — 358 Mo telecharges au demarrage du worker (`panns_files.py` : Zenodo puis miroir Hugging Face, SHA-256 verifie, reprise) ; facultatif : s'il manque, l'analyse continue sans rires / cris (notice `audio_events`)
- **Transcription** : Whisper large-v3 turbo ; en « auto », le plus rapide : Groq si sa cle est la (un live de 7 h en 25 s, ~0,04 $/h), sinon en local quand la machine est rapide (mlx-whisper sur puce Apple, faster-whisper sur NVIDIA), sinon OpenRouter — `transcriber.py`, bascule sur OpenRouter si le moteur choisi coince (limite horaire du Groq gratuit comprise)
- **LLM** : OpenRouter — Gemini 3 Flash Preview (audio + vision + analyse + scoring) ; recherche dans le live : GPT-6 Luna avec des outils (repli : Claude Haiku 5.5), Gemini 3.1 Flash Lite pour ecouter un passage ; plan d'une video decrite : GPT-6.1 Terra (voir « Recherche par l'IA »)
- **Video** : FFmpeg, OpenCV, yt-dlp
- **Storage** : disque local `<data dir>/storage/{clips,renders,assets}`, servi par l'API via URLs signees
- **Tests** : Vitest (frontend + backend unit/functional)

## Commandes

```bash
# Tout lancer en dev (API HMR + worker auto-reload + Vite, data dir partage <repo>/.data)
npm run dev                         # http://localhost:5173

# Mode "comme l'app desktop" : API compilee qui sert le front build + worker
npm start                           # npm start -- --build pour forcer le rebuild

# App desktop (Electron, voir desktop/README.md)
cd desktop && npm run dev           # coque Electron sur le depot (apres un npm start)
cd desktop && npm run pack          # app empaquetee pour cet OS ; Cuttie --smoke-test=full --smoke-report=r.json

# Tests
cd frontend && npx vitest           # frontend tests
cd backend && uv run pytest         # backend tests
cd api && node ace test             # API tests (.env.test : data dir jetable, sans auto-login)
```

## Variables d'environnement

Les cles API (OpenRouter obligatoire, Groq et OpenAI facultatives) et le moteur de transcription (`transcription` : auto | groq | openrouter | local) se reglent dans la page **Parametres** de l'app → `<data dir>/settings.json` (relu a chaud par le worker). En dev, le worker retombe sur `GROQ_API_KEY` / `OPENROUTER_API_KEY` de `backend/.env`. Le modele Whisper local (1,5 Go) se telecharge dans `<data dir>/models/whisper`.

Positionnees par les lanceurs (`scripts/dev.mjs`, `scripts/launcher.mjs`) :
- `CUTTIE_DATA_DIR` — dossier de donnees partage (defaut `<repo>/.data`)
- `CUTTIE_INTERNAL_SECRET` — secret partage API <-> worker (header `X-Cuttie-Secret`)
- `WORKER_URL` (API) / `CUTTIE_API_URL` + `CUTTIE_WORKER_PORT` (worker)
- `CUTTIE_AUTO_LOGIN` (defaut true), `FRONTEND_DIST` (API sert le front build)
- `CUTTIE_APP_VERSION` (version de l'app desktop, dans l'export des journaux), `CUTTIE_CLEANUP_DAYS` (menage par defaut : 30 dans l'app installee, rien en dev)
- `CUTTIE_LLM_CMD` (dev seulement) : commande qui lit une invite sur stdin et ecrit la reponse, a la place d'OpenRouter pour les appels texte de `llm_text.py` (recherche IA, plan, montage IA) — ex. `claude -p --model sonnet --tools ""` — pour tester sans depenser de credits. Une commande ne peut pas appeler d'outils : avec elle, la recherche et le plan lisent tout le transcript en une fois (l'ancienne methode)
- `CUTTIE_SEARCH_MODEL`, `CUTTIE_SEARCH_FALLBACK`, `CUTTIE_EARS_MODEL`, `CUTTIE_EYES_MODEL`, `CUTTIE_PLAN_MODEL`, `CUTTIE_IDEAS_MODEL` : modeles de la recherche dans le live (celui qui cherche, celui qui prend le relais, celui qui ecoute, celui qui regarde (les images d'un moment du live, et les passages pour choisir leur modele), celui qui construit une video decrite, celui qui propose des compilations une fois le live analyse) ; `CUTTIE_MEMORY_MODEL` : celui qui lit un live pour la memoire de l'IA et la reecrit (defaut : celui qui cherche) ; `CUTTIE_SEARCH_MAX_COST` / `CUTTIE_PLAN_MAX_COST` / `CUTTIE_IDEAS_MAX_COST` : plafond d'une question (0,05 $), d'une video decrite (0,12 $) et du reperage des idees (0,05 $)
- `CUTTIE_AGENT_MODEL`, `CUTTIE_AGENT_MAX_COST`, `CUTTIE_AGENT_MAX_STEPS` : le modele de l'assistant (defaut : celui qui cherche), son plafond par demande (0,05 $) et son nombre d'etapes (24)

Fichier `api/.env` : voir `api/.env.example` (APP_KEY en dev ; l'app packagee genere `<data dir>/app.key`).

## Pipeline (6 etapes)

```
1. DOWNLOADING_AUDIO   -> Metadata + audio 16 kHz mono WAV + chat Twitch GQL (en parallele)
                          puis transcription du live entier en arriere-plan (morceaux de 10 min,
                          moteur local si rapide, repli OpenRouter par morceau ; ~11 min pour 5 h sur M1 Max)
2. ANALYZING_AUDIO     -> librosa features (5s/2.5s hop) + PANNs CNN14 16 kHz (rires, cris, parole ; en parallele)
                          puis index sonore du live pour les recherches (sound_index.py, ~30 s pour 5 h sur M1 Max)
3. ANALYZING_CHAT      -> Sentiment, emotes, burst, demandes de clip des viewers ;
                          decalage du chat estime (correlation son/chat, defaut 5 s)
4. SCORING             -> Score composite pondere + peak detection -> top 200
5. ANALYZING_CLIPS     -> Pour chaque candidat (sans download video) :
                          a. Texte de chaque candidat lu dans le transcript du live (sinon Whisper
                             sur les 200 segments ; morceaux rates -> job.notices)
                          b. Mot "clip" dit n'importe ou dans le live (15 max, demandes d'abord) ->
                             fenetre des 2 min avant, verifiee par le LLM (vraie demande = clip
                             "detected", garde quel que soit son rang)
                          b'. Pre-tri par l'IA (presort.py, 1 appel texte ~0,05 $) : lit tout le transcript
                             (une ligne / ~20 s) + les pics du chat -> jusqu'a 40 moments, fenetres
                             elargies (-10 s / +20 s, la reaction) ; un candidat qui chevauche prend la
                             fenetre de l'IA ; 15 des 50 places de l'etape f leur sont reservees ;
                             un moment trouve en lisant prend les mesures de la fenetre la plus forte
                             de son passage (scorer.ScoreTrack), marque found_by = "reading"
                          b''. Regard (watching.py, ~0,04 $) : la ou l'on parle peu mais ou quelque chose dit que
                             l'image compte (96 pistes au plus), 3 images de chaque piste sont regardees par le
                             petit modele qui voit, et l'IA qui cherche avec des outils est chargee de trouver les
                             memes scenes ; celles qui valent le coup d'oeil (10 au plus) ont des places reservees
                             a l'etape f, marquees found_by = "watching", et ce qui a ete vu (et les mots ecrits a
                             l'ecran) est donne au modele qui note (voir « Moments ou l'image est le moment »)
                          c. VOD context gathering (1 appel LLM text-only) :
                             - Lit les 200 transcripts chronologiquement
                             - Produit contexte VOD (narrative, phases, protagonistes, themes)
                             - Produit content_score par segment (heat map)
                             - Sauvegarde vod_context en base
                          d. Re-rank blende (50% heuristique + 50% content_score) -> top 50
                          e. En parallele :
                             - 6 frames par candidat via ffmpeg seek sur URL VOD directe
                             - Qui parle quand (speaker_diarizer.py, local, sans compte Hugging Face) :
                               Silero VAD + empreintes WeSpeaker ResNet34 (ONNX, 26 Mo) sur des fenetres

                               streamer = la voix retrouvee dans le plus de 12 passages repartis sur le live
                               → transcript avec labels speakers ([Streamer]: ..., [SPEAKER_01]: ...)
                          f. 1 appel LLM multimodal par candidat (audio + frames + speaker transcript
                             + chat recale + vod_context) -> score, titre, accroche, coupe conseillee, et ce que
                             le clip contient pour qui cherche des clips sans les regarder : `seen` (ce qu'on voit,
                             dit a plat, avec les mots ecrits a l'ecran) et `tags` (3 a 6 mots)
                          -> Re-rank par final_score, garde top 20
6. CLIPPING            -> yt-dlp video + FFmpeg extraction (bornes dynamiques RMS)
                          uniquement pour les 20 candidats gardes ; chaque fichier demarre sur sa premiere image
                          (voir « Decoupe »)
                          + reperage de la webcam sur les clips (facecam.json v3 : cadre + qui est ou, toutes les 4 s de chaque clip)
                          + mots des clips gardes transcrits sur leur audio si le live l'a ete sans
-> DONE
   puis, sans rien retarder : l'IA parcourt le live et propose des compilations (voir « Compilations proposees par l'IA »)
   et le lit en entier pour sa memoire (voir « Memoire de l'IA »)
```

Fournisseur qui refuse tout (`provider_errors.py`) : credits OpenRouter epuises (402) ou cle refusee (401) -> l'analyse s'arrete avec un message clair et une notice `provider` (lien « Recharger mes credits » dans l'app), jamais de repli silencieux sur le score heuristique. Verifie aussi au demarrage (1 token) et dans le diagnostic.

## Scoring

**Score heuristique** (normalisation baseline-relative, median/P95 ; chat lu `chat_lag` s plus tard) :
- chat_speed 18%, onset 14%, pitch_var 14%, spectral_flux 12%, RMS 10%
- chat_burst 10%, emote_density 8%, caps_ratio 7%, centroid 5%, zcr 2%
- Multiplicateurs : accord son + chat (x1,3 max), sentiment du chat, voix forte ; son de jeu seul (x0,85)
- Bonus additifs : excitation vocale PANNs (+0,25), viewers qui demandent un clip (+0,3 a partir de 2)

**Pre-filtre** : `0.5 * heuristique + 0.5 * content_score_LLM` (+ bonus/malus content gems/false positives)

**Score final** : `0.2 * heuristique + 0.8 * LLM virality`

**Coupe conseillee** : le clip extrait garde ses marges (45-90 s) ; le LLM propose `cut_start` / `cut_end` (15-45 s en general), appliques comme trim par defaut dans Choisir et Monter tant que le streamer n'a pas coupe lui-meme.

## Un parcours par live, et un assistant

Demandes de Corentin (23/11/2026). La première unification (« Trois sources, une seule video », plus bas) a été refusée : des onglets Clips / Séquences / Compilations qui menaient à une autre page, deux écrans « Clips ». « Remets tout à plat, et conçois une interface cohérente de A à Z », puis, sur maquette : un assistant « complet, sticky, contextuel » dans un panneau latéral qui « pousse toute la page à gauche », qui répond et agit (« analyse mon dernier live », « découpe-moi ce clip », « cherche les passages où je dis à l'aide et ajoute-les »), pour que Monter ne soit plus que la timeline, l'habillage et les passages ; sur LangChain deepagents (son choix) ; des suggestions contextuelles et des widgets ; pas le « pauvre logo étoiles ». La maquette cliquable validée est dans `.claude/notes/previews/maquette-interface.html` (hors dépôt).

- **Deux objets, un parcours** : le live et la vidéo. Un live a quatre étapes, les mêmes pour les trois sources (`LiveHeader`, `Stepper`) : Analyse → Choisir (`/:jobId`) → Monter (`/:jobId/montage`) → Exporter (`/:jobId/export`). La barre du haut : Accueil · Lives (`/projects`) · Vidéos (`/compilations`, tout ce qui est gardé, tous lives confondus) · Ma chaîne.
- **Choisir** (`ProjectPage`) : une seule liste en trois sections (clips, séquences, compilations : `SourceList`, `lib/liveEntries.ts`), le meilleur d'abord, « Voir les N autres », « Ajouter… » en bas de chaque section, une infobulle sur chaque nom de source (`SourceName`). Le même volet de détail et les deux mêmes décisions, Passer / Garder. Garder un clip en fait une vidéo (tout de suite) ; garder une idée de l'IA la fait construire (≈ 0,04 $). On n'y coupe plus rien : la coupe se fait dans Monter. `?clip=<fichier>` / `?video=<id>` : ce qui est montré d'abord.
- **Monter** (`CompilationPage`, la même page pour les trois sources) : en haut les vidéos gardées par source (`VideoRail`, une source vide propose « Ajouter une… ») ; à gauche les passages, au centre la vidéo, à droite l'habillage (`CompilationPanel part="passages" | "look"`) ; dessous la timeline de toute la vidéo (`VideoTimeline` : parties, passages, niveau de la musique, tête de lecture) avec les outils de coupe (couper ici, enlever les silences, ± 30 s, Montage IA sur un clip, annuler) ; puis le passage ouvert. Une vidéo vide se décrit au centre, là où elle jouera (`DescribeVideo` : la décrire à l'IA, ou construire l'idée que l'IA a proposée) ; « Chercher dans le live » (mots, question à l'IA) prend la place des passages le temps de chercher (`SearchPanel`). L'habillage est une liste de groupes (image, texte, mouvement, son) dont chaque ligne s'ouvre sur place.
- **Exporter** (`ExportStepPage`) : les vidéos gardées par source, cochées quand elles n'ont jamais été exportées ou ont changé depuis, exportées à la suite sans ouvrir leur montage (`lib/videoExport.ts`, `lib/videoBuild.ts`).
- **Garder une idée la construit derrière la page** (`lib/backgroundBuild.ts`, demande de Corentin : « je veux pas que ça m'ouvre la page Monter, je veux que l'IA travaille en arrière-plan ») : on reste sur Choisir ; l'idée dit « L'IA construit la vidéo » et ce qu'elle fait, puis rejoint les vidéos gardées (plan, passages découpés et calés sur leurs mots, ramenée à sa durée, musique / ouverture / transition choisies : ce que fait Monter quand on y décrit une vidéo, sans Monter). Une à la fois, les autres attendent ; changer de page ne l'arrête pas (recharger la page, si). Monter, ouvert sur une vidéo en cours de construction, le montre et la prend une fois finie ; sa rangée de vidéos gardées (`VideoRail`) montre aussi celles que l'IA construit, ici ou derrière la page, avec ce qu'elle fait à la place de la durée. Vérifié à l'écran avec un plan simulé (rien dépensé) ; pas avec le vrai plan.
- **La barre du haut** (`TopBar`) : trois groupes, toujours dans cet ordre : où l'on est (logo, puis Accueil · Lives · Vidéos · Ma chaîne, chacun avec son icône), ce qui demande quelque chose (clé manquante, mise à jour), ce qui est à soi (le menu de la chaîne : Paramètres, Fichiers exportés) et, tout à droite, l'assistant, dont le panneau s'ouvre sous son bouton. Elle se met en page sur sa propre largeur (requêtes de conteneur), pas celle de la fenêtre : l'assistant ouvert la rétrécit et elle retire les noms puis les indications au lieu de passer à la ligne. Sur téléphone (< 768 px) les quatre lieux sont une barre d'onglets en bas, et l'assistant couvre la page au lieu de la pousser (< 1024 px). Le menu a un fond plein : un flou dans le flou de la barre laissait voir la page.
- **Dans un sous-menu de l'habillage**, le bouton principal est « Retour à l'habillage » (l'export attend sur la vue d'ensemble).
- **Mise en page selon la place réelle** (demande de Corentin, 24/11/2026 : « quand l'écran devient plus petit, le layout est chaotique » : les colonnes passaient à la ligne au hasard). Choisir et Monter se mettent en page sur la largeur qu'ils ont vraiment (requêtes de conteneur dans `app.css` : `.chooser`, `.workshop`), donc aussi quand l'assistant ouvert en prend 420 px. Monter : trois colonnes à partir de 1040 px ; entre 640 et 1040 px la vidéo à gauche et un seul panneau à la fois à droite (onglets « Passages · N | Habillage ») ; en dessous tout s'empile (vidéo, onglets, panneau). La vidéo n'est jamais plus large que sa colonne. Choisir : le lecteur à côté de la liste, la liste plus étroite quand il y a moins de place, l'un sous l'autre sous 640 px. La rangée des vidéos gardées est une bande d'une ligne qui défile de côté (`.scroll-row`) au lieu de couper une source en deux. Vérifié à l'écran à 375, 915 et 1560 px, assistant ouvert et fermé.
- **Écrans retirés** : l'ancien Monter des clips (`MontagePage`), le sélecteur `ModeSwitch`, la page des vidéos d'un live, le guide en 4 étapes, la conversation d'une vidéo décrite (`PlanTalk`) : elle est celle de l'assistant. `/:jobId/compilation` et `/:jobId/compilations` redirigent.

### La timeline se manipule

Demandes de Corentin (24/11/2026) : la timeline « manque un peu d'interactivité » (déplacer le curseur en le faisant glisser, réordonner les passages par glisser-déposer), « sélectionner plusieurs tranches » (Cmd / Ctrl + A, Cmd / Ctrl + clic) pour leur appliquer le Montage IA ou « Enlever les silences » d'un coup, et, sur capture, le sélecteur « 30 s · 1 min · 1 min 30 · 3 min » sous les passages : « on sait plus trop à quoi ça sert ».

- **Tête de lecture** (`VideoTimeline`) : un appui n'importe où sauf sur un passage (règle, piste des parties, musique) y amène la vidéo, qui suit le pointeur tant qu'il est tenu ; elle a un bouton en haut pour l'attraper sans qu'elle saute, l'heure au dixième s'affiche au-dessus pendant le geste (`scrubClock`). La vidéo se met en pause le temps du geste et reprend ensuite ; l'image suit une fois par rafraîchissement d'écran. Au clavier : flèches (1 s, 5 s avec Maj), Début, Fin.
- **Passages glissés** : un passage se prend et se pose ailleurs, d'une partie à l'autre aussi ; un trait de la couleur de la chaîne dit où il tombera (`timelineDrop.dropPlace` : avant le passage dont la première moitié est sous le pointeur, après celui dont c'est la seconde ; entre deux parties, à la fin de la première tant qu'on est sur son dernier passage). Moins de 6 px : c'est un clic. Échap annule. Les passages sélectionnés partent ensemble (`placeItems`). Un pas d'annulation (Ctrl + Z).
- **Sélection** (`usePicked`, une seule pour la liste des passages et la timeline) : Cmd / Ctrl + clic ajoute ou retire, Maj + clic prend tout jusqu'au dernier pris, Cmd / Ctrl + A tout, Échap rien ; un clic simple sur un passage de la timeline ne garde que lui. La barre de la timeline dit « N sélectionnés » à la place des deux boutons « 30 s » (qui ne valent que pour un passage : la barre ne change pas de largeur, donc rien ne saute sous le pointeur).
- **Outils sur la sélection** : « Enlever les silences » et « Montage IA » travaillent sur chaque passage sélectionné, en un seul changement de la vidéo (`cutItems`). Le Montage IA d'un passage ne montre à l'IA que la part de son fichier que le passage joue (`within`, worker `suggest_cut` : cette part seule, comme si elle était tout le clip) ; il vaut maintenant pour tout passage, moment du live compris. La durée visée est celle de toute la sélection : chaque passage en reçoit sa part. Un appel par passage (moins d'un centime chacun).
- **« Raccourcir à… »** remplace le sélecteur de durée sous les passages : un bouton, présent seulement quand la vidéo est plus longue qu'une des durées (30 s, 1 min, 1 min 30, 3 min), qui agit tout de suite (`fitToTarget`) et dit ce qui s'est passé (« Vidéo ramenée à 0:40 : 2 passages retirés »). La durée choisie reste celle que l'IA vise quand on lui demande un changement.
- Vérifié à l'écran (instance de test) : tête de lecture tirée par son bouton (0:00 → 0:14,9) et posée par un clic sur la règle ; dernier passage glissé en tête, d'une partie à l'autre ; trait de dépôt et Échap pendant un geste ; deux passages pris par Cmd + clic (cochés aussi dans la liste), « Enlever les silences » sur les deux (un coupé en trois, l'autre laissé), Cmd + A (10 sur 10) ; Montage IA sur deux passages avec des réponses simulées (deux appels, chacun avec sa part du fichier) ; « Raccourcir à 30 s ».
- Limites : le Montage IA sur plusieurs passages n'a pas tourné avec le vrai modèle ; pas de rognage d'un passage en tirant son bord dans la timeline (ça se fait dessous, dans le passage ouvert) ; la vidéo repart du début après un déplacement (le lecteur est recréé) ; pas de zoom ni de défilement de la timeline (un passage très court dans une longue vidéo est étroit) ; pas essayé au doigt sur un écran tactile.


### L'assistant

- **Worker** (`backend/app/services/assistant.py`, `assistant_tools.py`) : un agent LangChain deepagents (`create_deep_agent`, sans ses outils de fichiers ni de liste de tâches), modèle par OpenRouter (`CUTTIE_AGENT_MODEL`, défaut : celui qui cherche ; `CUTTIE_AGENT_MAX_COST` 0,05 $ et `CUTTIE_AGENT_MAX_STEPS` 24 par demande), conversation gardée dans `<data dir>/assistant/threads.sqlite`. Ses outils : lire un live (les outils de la recherche : `live_tools`), `find_moments` et `find_video_ideas` (les recherches existantes), `list_lives` / `list_clips` / `list_videos` / `get_video`, `list_imported_videos` (la médiathèque), `keep_clip`, `analyse_live` (demande l'accord d'abord), `show` (des cartes dans la réponse), et les actions faites par l'app à l'écran : `open`, `build_video`, `change_video`, `add_passages`, `add_imported_videos`, `cut_clip`, `set_look`, `export_videos`. Une action pour l'app ou une demande d'accord interrompt la conversation (`interrupt`) jusqu'à la réponse.
- **API** (`assistant_controller.ts`, `services/assistant.ts`) : la conversation est gardée par l'API (`<data dir>/assistant/conversation_<user>.json`), une demande à la fois ; `GET /api/assistant`, `POST /api/assistant/turn { text | resume: { call, result }, context, language }`, `GET /api/assistant/progress`, `DELETE /api/assistant`. Ce que l'assistant demande à l'app pendant qu'il travaille : `POST /api/internal/assistant { tool, args }` (secret partagé) : `lives`, `live_meta`, `clips`, `videos`, `video`, `media` (la médiathèque), `keep_clip`, `ideas`, `start_analysis`, toujours pour le streamer à qui il répond. Les cartes d'une réponse sont complétées ici (nom, durée, image).
- **App** (`lib/AssistantContext.tsx`, `components/AssistantPanel.tsx`, `components/assistant/`) : un panneau à droite qui prend sa largeur à la page (Ctrl / Cmd + J). Chaque page dit où est le streamer (`useAssistantPlace` : page, live, clip ou vidéo à l'écran, et quelques chiffres : clips à trier, idées, ce qui manque à une vidéo) ; c'est envoyé avec chaque demande. Une action sur une vidéo est faite par le montage du live (`useAssistantActions`, `assist` dans `CompilationPage`), ouvert d'abord s'il ne l'est pas ; son résultat (ou son erreur) est ce que l'assistant lit ensuite. `set_look` passe par `lib/assistantLook.ts` : ce que l'assistant nomme et que l'app n'a pas lui est redit avec ce qui existe (les pistes, les intros…). Une page relit ses données quand l'assistant a changé son live côté serveur (`useAssistantChanged`).
- **Suggestions** (`lib/assistantSuggestions.ts`) : jamais une liste fixe. Lues dans la page (le clip à l'écran, les idées qui attendent, une vidéo sans musique ou sans ouverture, ce qui reste à exporter, le dernier live pas encore analysé) et dans la dernière réponse (une idée montrée se construit, des vidéos s'exportent, des clips se gardent) ; certaines sont des phrases à finir (« Trouve les moments où… ») posées dans la zone de saisie. Les cartes agissent seules : construire une idée, exporter un lot, garder un clip, écouter un passage et l'ajouter (ou « Tout ajouter »).
- **Une demande aidée** (`components/assistant/Composer.tsx`, `assistant.compose`) : « Ajouter avec l'IA », dans les passages de Monter, ouvre le panneau sur un champ fait pour ça (« Les moments où… », combien au plus, dans quelle partie) ; il en fait une phrase, envoyée comme une autre.
- **Sa marque** (`components/assistant/Mark.tsx`) : un morceau de son (quatre barres) traversé par une coupe, sur une tuile de la couleur de la chaîne posée de travers ; les barres bougent quand il travaille. Elle remplace l'étoile dans le panneau et sur son bouton.
- Vérifié à l'écran (instance de test, modèle remplacé par des réponses simulées dans le navigateur, puisque `CUTTIE_LLM_CMD` ne sait pas appeler d'outils : l'assistant répond alors « a besoin d'un vrai modèle ») : une demande part avec où l'on est ; `cut_clip` ouvre le clip dans Monter et renvoie son erreur à l'assistant ; `set_look` change effets, transition et ouverture et redit la musique inconnue avec la liste des pistes ; « Tout ajouter » ajoute les passages d'une carte à la vidéo ; la demande d'accord (0,30 $) et son « Non ».
- **Essai réel** (24/11/2026, instance de test, GPT-6 Luna, le live GTA 6 de 4 h 10 ; 0,004 $ en cinq demandes d'après le compteur de l'app, 6 à 20 s chacune) : « Trouve les moments où il dit what the fuck » → 4 passages montrés dans une carte (dont le tigre à 3:43:27), 0,001 $ ; « une musique plus posée, des effets légers et une transition qui glisse » → les effets changés, mais « musique posée » et « glisse » inconnus de l'app et l'assistant s'arrêtait là ; corrigé (l'app comprend les noms affichés à l'écran : « Glissé », « Marqués », « Flash info »… ; une piste inconnue lui est redite avec toutes les pistes et ce que chacune est ; il choisit alors et rappelle `set_look` une fois) : « une musique qui tabasse et une transition rebond » dans une conversation neuve → Trap Hype Beat et Rebond en deux appels, 0,0009 $ ; « cherche les passages où il dit what the fuck et ajoute-les à la fin » → 4 passages ajoutés à la dernière partie, 0,0004 $, dont un que la vidéo avait déjà (la même phrase, datée 5 s plus tôt par le transcript) : corrigé (`compilation.saidAlready` : les mêmes mots à moins de 20 s).

## Trois sources, une seule video

(Première tentative, du 23/11/2026, refusée par Corentin et remplacée par « Un parcours par live, et un assistant » ci-dessus. Restent vrais : les trois sources, `compilation.source`, `from-clip`, les effets par défaut. Ne sont plus vrais : les onglets de la bibliothèque, `ModeSwitch`, l'ancien parcours des clips à côté.)

Demande de Corentin (23/11/2026) : « c'est trop bizarre d'avoir toutes ces differences », avoir les trois sources (clips, sequences, compilations) « a la meme echelle » et unifier tout le processus apres ; s'inspirer des compilations (« le dernier truc qui a ete fait, la bonne direction ») ; que l'IA serve a construire les trois (« vers 3 heures a peu pres, je me souviens qu'il s'etait passe ca ») et a modifier n'importe quelle video ; un soin particulier a l'interface. Premiere version, faite pour iterer dessus.

- **Une video, trois sources** (`frontend/src/lib/videoSources.ts`, `compilation.source` ; l'API tient la meme liste, `compilations.VIDEO_SOURCES`, egale par un test) : un clip (un moment, environ une minute), une sequence (un passage d'affilee raconte en une video), une compilation (des passages pris partout, la seule a prendre dans plusieurs lives). Apres sa source une video est la meme chose : des passages, un habillage, un export. Techniquement toutes sont des compilations (`jobs.compilations`) ; sans `source`, une idee de l'IA avec `span` est une sequence, le reste une compilation (`sourceOf`).
- **Un clip de l'analyse s'ouvre comme une video** (`POST /api/jobs/:id/compilations/from-clip { clip }`) : un passage (la coupe du streamer, sinon celle de l'IA, sinon tout le clip, placee dans le live d'apres le debut reel du fichier), son accroche en titre a l'ecran, l'univers du jeu, des effets legers, pas d'intro. Son fichier est celui du clip, copie en `piece_<id>.*` (rien n'est repris du live ; un clip d'avant `settled` est decoupe a l'ouverture comme un passage). Rouvert, c'est la meme video (`compilation.clip`). Ce que l'analyse en a vu (`seen`, `narrative`) ouvre son fil avec l'IA.
- **La bibliotheque** (`CompilationsPage`, toujours `/compilations` et `/:jobId/compilations`, titre « Videos », `?kind=clip|sequence|compilation`) : trois onglets au meme niveau. Clips : les clips de l'analyse pas encore ouverts (`lives[].clips`, carte `ClipCard` : image, note, duree, titre, ce qu'on y voit, tags, « Repere a l'image » pour ceux trouves en regardant, « Garde ») et les clips deja ouverts ou demandes a l'IA ; Sequences et Compilations : leurs idees et leurs videos. Une tuile « Nouveau clip / Nouvelle sequence / Nouvelle compilation » par onglet.
- **Le selecteur** (`ModeSwitch`, sur toutes les pages d'un live) : Clips · Sequences · Compilations, chacun vers l'onglet de la bibliotheque du live ; le nombre d'idees qui attendent est sur la source dont elles sont (`suggestions.waitingBySource`). L'entree « Compilations » de la barre du haut s'appelle « Videos ».
- **L'editeur est le meme pour les trois** (`CompilationPage`) : il dit la source (retour, sous-titre, « Nouveau clip »), et s'allege pour un clip (`CompilationPanel`, `source`) : pas de parties ni de titres de parties, une ligne « Titre a l'ecran », pas de transitions tant qu'il n'y a qu'un passage, pas de « Ajouter un live » hors compilation. Tout l'habillage vaut pour les trois (univers, modele, style des titres, effets, intro, musique, « Laisser l'IA choisir »).
- **L'IA construit les trois et modifie chacune** : « Decrire la video » envoie la source (`/plan`, `source`), et l'API met devant les mots du streamer ce qui est demande (`BUILDS` dans `compilations_controller` : un clip = un seul moment de 30 a 75 s d'affilee en une partie, une sequence = un passage d'affilee raconte dans l'ordre ; une heure donnee, meme a peu pres, est l'endroit ou lire d'abord). Le fil « Demande un changement » est la sur toute video, clip de l'analyse compris.
- **Une nouvelle video a des effets legers par defaut** (`store`, `from-clip` ; `effects: null` a la creation pour n'en avoir aucun), la ligne « Effets » les retire.
- Verifie a l'ecran (instance de test, le live GTA 6 analyse) : l'onglet Clips (20 cartes, la poursuite en hydroglisseur marquee « Repere a l'image »), l'onglet Sequences (2 idees, la mission du yacht construite), un clip ouvert d'un clic dans l'editeur commun, joue tout de suite dans la mise en page GTA avec son titre sur l'encadre, son fil avec l'IA et l'habillage complet.
- Limites : **pas essaye avec le vrai modele** : ni « Nouveau clip » decrit a l'IA (« vers 3 h... »), ni un changement demande sur un clip (environ 4 centimes chacun) ; l'ancien parcours des clips (Choisir, Monter, Exporter) existe toujours a cote, avec ses reglages dans le navigateur : rien n'est encore migre, et un clip peut donc se monter de deux facons ; les outils de coupe de Choisir (couper ici, enlever les silences, Montage IA, + 30 s) ne sont pas dans l'editeur commun (un passage n'y a que ses deux poignees) ; garder / passer ne se fait que dans Choisir ; un clip ouvert comme video duplique son fichier (une cinquantaine de Mo) ; les exports ne sont pas encore reunis en une liste ; le guide « Comment ca marche » ne parle que des compilations.

Demande de Corentin (23/11/2026) : dans un jeu ou le streamer est beaucoup spectateur (GTA, mais pas que), ce qui est drole n'est souvent pas sa reaction : une scene « what the fuck » se joue devant lui, il reste bouche bee et dit trois mots. Ses moments notes 60 ou plus rejoignent les scenes des pistes.

## Montage dynamique

Demande de Corentin (23/11/2026) : « plus de reactivite, des zooms, des petits tremblements de camera ; quand quelqu'un dit un truc drole, un zoom », comme dans les videos qui marchent, partout (clips, sequences, compilations), et « si c'est nul, il faut pouvoir l'enlever ».

- **Trois mouvements** (`frontend/src/lib/effects.ts`, copie dans `api/remotion/effects.ts` par `scripts/sync-remotion.mjs` : le meme calcul pour l'apercu et l'export) : `zoom` (un passage sur deux joue un peu plus pres, pour qu'une coupe entre deux passages de la meme scene se lise comme une coupe), `punch` (l'image se rapproche en un dixieme de seconde sur une replique qui porte, tient, revient), `shake` (une secousse d'un tiers de seconde qui s'eteint, l'image un peu rapprochee pour que ses bords ne se voient jamais). Rien ne change de duree, aucun son ne bouge.
- **Ou ils vont** (`placeEffects`, sans IA) : la replique qui porte = un mot qui finit par « ! » ou « ? » dans les mots dates du passage (le coup de zoom part la ou commencent ses trois derniers mots), ou les temps forts donnes pour un clip (`beats`, prevu pour les `key_moments` de l'analyse). Niveau « leger » : zoom alterne a 1,05, un coup de zoom a 1,08 de 0,8 s sur la derniere replique qui porte ; « marque » : 1,08, deux coups de zoom a 1,14 avec une secousse. Pas dans un passage de moins de 2,5 s, ni a moins d'une demi-seconde de ses bords.
- **Chaque image bouge dans son cadre** (`MontageComposition`, `Layers`) : seuls le jeu et la cam bougent, chacun decoupe a sa propre boite et autour de son centre, a sa place dans la pile ; les cadres qu'une mise en page dessine autour, les sous-titres et les titres ne bougent pas. Les boites sont toujours dans l'arbre (sans existence tant que rien ne bouge) : une video n'est jamais remontee quand un effet commence, ce qui la relancerait dans l'apercu.
- **Donnees** : `compilation.effects` (`"light"` ou `"strong"`, absent : aucun effet), ligne « Effets » de l'habillage (Aucun, Legers, Marques) ; `MontageSegment.effects` jusqu'au rendu ; le serveur garde le niveau (`compilations.EFFECT_LEVELS`, egal a celui de l'app par un test) et ne rend que les effets qu'il connait (`cleanEffects`).
- **Ce que les exports reels ont montre** (meme sequence de 1 min 30, niveau « marque », quatre exports) : d'abord les images du passage disparaissaient pendant chaque effet (cadres noirs) : tout le passage devenait une seule boite qui passait sous les cadres de la mise en page GTA, ranges chacun sous son image ; puis, chaque calque deplace en entier, l'image sortait de son cadre. Quatrieme export : sur neuf images sorties, la cam et le jeu sont dans leurs cadres, plus pres sur un passage sur deux, sous-titres et titres en place.
- Limites : **les clips classiques (Monter) et les clips coupes en morceaux n'ont pas encore d'effets** (seulement les compilations et les sequences) ; aucun effet par defaut, meme sur une video construite par l'IA ; pas de reglage par passage ; regarde sur des images fixes de l'export, pas en mouvement par quelqu'un : le dosage (1,05 a 1,14, 0,8 s) est un premier jet ; le coup de zoom suit la ponctuation de la transcription, pas le volume de la voix ni un rire ; pas de son d'effet ; les transitions gardent leur ancienne facon de faire (tout le passage dans une boite) : sur la mise en page GTA a cadres, l'image doit disparaitre un tiers de seconde a chaque transition (pas verifie, pas corrige) ; pas repris dans l'editeur a calques.

## Recherche par l'IA

« Demander a l'IA » et « Decrire la video » (ecran Compilation) : un modele qui appelle des outils, pas une lecture du transcript en une fois (essayee d'abord : 1 bon passage sur 4, et rien sur « les moments ou ca pete »).

- **Outils** (`live_tools.py`, chacun repond peu et exactement, heures en H:MM:SS) : `overview` (titre, jeu, resume, phases), `best_moments` (les 50 moments notes par l'analyse, clippes ou non : score, genre, nom, ce qui s'y passe ; l'API les envoie depuis `jobs.timeline.candidates`, le worker n'ayant garde que les 20 clippes), `search_speech` et `search_chat` (mots dits / ecrits), `chat_peaks` (la ou le chat s'emballe : rafales de messages bien au-dessus de son rythme, d'au moins 2 viewers), `find_sounds` (22 familles : coups de feu, cris, rires, sirenes...), `loud_moments` (voix qui montent, plus fort, silences), `read` (ce qui se dit entre deux heures, le chat, ce qu'on entend), `listen` (30 s du live envoyees a un petit modele qui entend, 12 ecoutes au plus), `look` (3 images d'un moment, sur 12 s au plus, envoyees a un petit modele qui voit : un kill, une victoire, un accident, un visage ; 8 regards au plus, ~0,0005 $ chacun, images prises dans la VOD en 480p), puis `answer` (ou `plan` pour une video) qui termine.
- **Index sonore** (`sound_index.py`) : PANNs ecoute tout le live par fenetres de 2 s, une par seconde ; fait pendant l'analyse, ou a la premiere question pour les lives analyses avant (son retelecharge : 2 a 3 min, une seule fois). Il se trompe (une moto passe pour des coups de feu) : il dit ou regarder, l'IA confirme en ecoutant.
- **Consignes** (`live_agent.py`) : comprendre l'argot comme le streamer l'entend (« ca pete » = l'action eclate), verifier chaque passage (`read`, `listen`), noter honnetement (80-100 exact, 50-79 plus doux, moins de 50 seulement proche), ne jamais remplir ; s'il n'y a rien, donner les passages les plus proches avec ce qui manque. Un plan de video qui fait moins des trois quarts de la duree demandee est renvoye une fois au modele.
- **Un passage = des lignes** : l'IA donne l'heure de la premiere ligne a garder et celle de la derniere, recopiees de `read` (au dixieme de seconde : deux lignes courtes ne se confondent pas). Les lignes du transcript local durent « 6 s » pour une phrase de 2 s : `read` et `search_speech` disent donc le temps qu'une ligne prend a dire (0,22 s par mot + 0,4 s sans mots dates), et c'est avec ca que l'IA et la relance comptent la duree de la video. Les vraies bornes viennent ensuite du clip (voir « Coupes calees sur les mots »).
- **Une video decrite** (`plan`) a son propre modele : trouver des passages est une chose, lire ce que veut dire chaque partie d'une description et y ranger les passages en est une autre. Consigne : ranger par ce qui se passe, pas par les mots communs (quand les parties racontent un avant et un apres, celui qui reparle de ce qui a ete dit, s'en moque ou le reproche va dans l'apres), et chercher la suite d'abord autour des passages de la partie d'avant.
- **Narration** (question de Corentin : les consignes insistent-elles sur le hook et le storytelling ? Pour un clip classique oui : accroche, coupe de la mise en place a la chute. Pour une video decrite, non : elles ne parlaient que de trouver et de ranger les passages). Le plan recoit maintenant ce qui fait un short (`live_agent._STORY`) : le premier passage est l'accroche (court, compris sans explication), chaque passage se comprend seul ou grace au precedent, le dernier est la chute (jamais une mise en place, une phrase qui s'eteint ou un au revoir), les titres des parties et `hook` (ce qui s'ecrit a l'ecran pendant les premieres secondes, rendu avec le plan et pose sur `compilation.hook`) sont des accroches, pas des etiquettes. Dans une suite de moments du meme genre l'ordre est libre (un fort d'abord, le plus fort a la fin) ; une histoire reste dans l'ordre du live. Un plan dont le premier passage dure plus de 5 s est renvoye une fois (`_slow_opening`, avec le plan trop court : `_to_redo`) : la consigne seule ne suffisait pas (ouverture de 11 s au premier essai). Les idees de compilations doivent avoir une accroche et une fin, et leur demande dit sur quoi la video s'ouvre et se termine. Mesure (15/11/2026, 2 videos refaites, 0,08 $ en 3 plans) : titres devenus des repliques (« Regarde sous l'escalier ! », « Il est en craquage ») au lieu d'etiquettes (« L'appel et les explications »), accroche ecrite (« La garde de trop ? »), ouverture passee de 10,7 s a 2,6 s sur l'une et restee a 6,5 s sur l'autre, meme nombre de passages et duree tenue. Ce que ca ne fait pas : l'IA garde l'ordre du live et ne met pas d'elle-meme le moment le plus fort en ouverture ; une fin plate est restee plate. L'ouverture a froid (le moment le plus fort joue avant tout, puis rejoue a sa place) existe depuis comme une intro : « Hook », voir « Intro ».
- **Ce qu'elle n'a pas** : la video en continu (elle ne la regarde pas d'un bout a l'autre : ce qui s'y passe lui vient des resumes de `best_moments`, ecrits par l'analyse qui a vu des images, et `look` ne lui montre que trois images d'un moment qu'un son, le chat ou l'analyse lui a deja designe : il confirme, il ne fouille pas ; un kill que rien ne signale reste invisible) et les courbes entieres (elle recoit des pics : 20 par demande, espaces de 15 a 45 s). Le modele qui ecoute repere bien une sirene ou un choc, mal une vraie colere (il decrit presque tout comme « ca plaisante »).
- **Garde-fous** : 28 etapes (36 pour un plan), 0,05 $ par question au plus et 0,12 $ par video decrite (la reponse est alors forcee), connexion coupee reessayee 3 fois, modele de repli si le premier echoue (plan : Terra, puis Luna, puis Haiku), credits epuises ou cle refusee dits tels quels. Les modeles Claude ne gardent en cache ce qu'on leur envoie que si on le demande (`cache_control`) : sans, chaque etape repaie toute la conversation (mesure : 0,0025 $ -> 0,0003 $ l'appel). Les tests ne peuvent joindre aucun fournisseur (`tests/conftest.py`).
- **Reponses gardees** : une recherche par l'IA, une video decrite et les idees de compilations sont gardees sur le disque du worker (`transcripts/<job>/search`), rangees par question, live, modele, version des consignes (`ANSWERS_VERSION`) et **version de l'app** (`live_search.answered_by`, `CUTTIE_APP_VERSION`) : apres une mise a jour, rien de ce que l'ancienne version a repondu n'est resservi. Avant, trois versions de suite (0.2.0 a 0.2.2) resservaient la reponse de la premiere alors que l'IA avait change de 300 lignes entre-temps : l'ami qui retapait sa description ne voyait aucun progres. En dev (pas de version), les reponses restent jusqu'au prochain changement d'`ANSWERS_VERSION`. Quand une reponse vient du disque, l'app le dit et propose « Redemander » (`fresh: true` sur `/search` et `/plan`) : l'IA cherche a nouveau, la nouvelle reponse remplace l'ancienne sur le disque et, pour une video decrite, dans la compilation a l'ecran. Un changement demande dans le fil n'est jamais garde.
- **Choix du modele** (14/11/2026, 9 modeles, 8 requetes sur un live de 4 h 43, 68 recherches, chaque passage juge ; 1,02 $ en tout) : GPT-6 Luna, precision 0,91, 76 % des bons passages trouves, 0,002 $ et ~20 s par recherche ; Claude Haiku 5.5 0,84 / 71 % / 0,005 $ ; Gemini 3 Flash 0,83 / 62 % / 0,014 $ (jusqu'a 0,07 $) ; GLM 5.3 0,78 / 58 % / 0,010 $ ; DeepSeek V4.1 Flash 0,78 / 40 % / 0,014 $ et 2 min ; Kimi K3 0,73 / 58 % / 0,083 $. Aucun de ces modeles n'a besoin d'entendre : l'ecoute passe par Gemini 3.1 Flash Lite (~0,0004 $ les 15 s).
- **Choix du modele du plan** (14/11/2026, catalogue OpenRouter du jour : 189 modeles recents avec outils ; 9 essayes sur la vraie demande d'un streamer, 2 parties, live de 6 h 49, compares aux 31 passages qu'un monteur (Fable 5.2, a la main) avait gardes ; 0,36 $ en tout) : GPT-6 Luna met toute phrase contenant le mot dans la 1re partie et trouve 0 a 2 des 20 passages de la 2e (0,004 $) ; Luna en effort moyen 2 (0,012 $, 2 min 30) ; Claude Haiku 5.5 3 a 5 (0,012 $) ; Gemini 3.5 Flash Lite 5 sans verifier (0,011 $) ; Claude Sonnet 5.5 7, video trop courte (0,09 $) ; Gemini 3.8 Flash 8 (0,10 $, plafond atteint) ; Muse Ember en erreur ; **GPT-6.1 Terra 14 puis 11 en deux essais, ranges juste, a la duree demandee, 0,03-0,04 $ et 45 s**. Limites : une seule demande, un ou deux essais par modele, les gammes au-dessus (Opus, Fable, Astra : 4 a 10 $ le million) non essayees.

## Compilations proposees par l'IA

Une fois un live analyse, l'IA le parcourt toute seule et propose des compilations a faire (demande de Corentin : « tout le monde dit dix fois que c'est calme puis ca part dans tous les sens », les kills, les fous rires...). Chaque idee attend d'etre ouverte : rien n'est construit, donc rien n'est paye, tant que le streamer n'en veut pas.

- **Reperer** (`live_ideas.py`, `Searcher.suggest`, GPT-6 Luna : 0,005 a 0,008 $ et 20 a 40 s, mesure sur 7 essais) : les outils de la recherche plus `recurring`, ce qui revient dans le live (mots et phrases de 1 a 4 mots dits sur beaucoup de lignes, et bien plus souvent que dans les autres lives du dossier de donnees quand il y en a : sans comparaison, les mots du jeu remontent aussi). Consigne : passer en revue chaque genre de compilation (phrase repetee, meme chose qui arrive plusieurs fois, histoire que le live raconte, chat qui s'emballe, best-of en dernier recours), compter, verifier 3 ou 4 moments de chaque idee, 5 idees au plus, jamais de remplissage. Avant que ses idees soient prises, le modele est renvoye une fois vers les phrases dites 10 fois ou plus qu'aucune idee ne couvre (`_unfollowed`) : sans ce filet, le « c'est calme » dit 25 fois avait ete oublie une fois sur les trois premiers essais.
- **Une idee** : titre, `brief` (la demande que le streamer aurait tapee, ecrite par l'IA a sa place, sans heures), duree visee, `pitch` (ce qu'elle a remarque, en une phrase), 2 a 4 tags, genre de video, note sur 100 (« indice de viralite » : une estimation du modele, rien de mesure), moments reperes (secondes du live). Ecartees : note sous 50, moins de 3 moments, pas de demande (`clean_ideas`). Reponse gardee sur le disque du worker : le meme live ne se parcourt qu'une fois.
- **API** (`suggestions.ts`) : chaque idee devient une compilation qui attend (`compilation.suggestion = { key, pitch, tags, kind?, score, moments }`, `brief` = la demande de l'IA, une partie vide) ; `jobs.suggestions` retient les idees deja proposees (une idee ecartee ne revient pas). Declenche par le dernier statut de l'analyse (`job_status_bus`, en arriere-plan, sans rien faire echouer), ou a la demande pour un live analyse avant (`POST /api/jobs/:id/suggestions`). `suggestion` appartient au serveur : ce que l'app envoie a ce sujet est ignore ; une copie n'est plus une idee de l'IA.
- **Construire a l'ouverture** : « Construire la video » ouvre la compilation avec `?build=1` ; l'editeur lance alors le plan avec la demande de l'IA et ses moments reperes (`leads`, donnes au modele du plan comme point de depart : 4 etapes au lieu d'une dizaine), exactement comme une video decrite (passages decoupes, recales, ajustes, musique et intro choisies). Le fil s'ouvre sur « Demande ecrite par l'IA a ta place », puis le streamer continue la conversation. Ouverte sans `build` (lien direct), l'idee montre ce que l'IA a remarque et attend le bouton : aucune depense sans clic. « Modifier la demande d'abord » rouvre le formulaire avec la demande.
- **Ecran** : carte a part dans la bibliotheque (`SuggestionCard` : resume, tags, anneau de l'indice, duree visee, moments reperes, prix de la construction, croix pour ecarter), les idees en tete de leur live ; pastille du nombre d'idees a decouvrir a cote de « Compilations » (`ModeSwitch`, tenue a jour par l'evenement `suggestions` du live) ; « N compilations trouvees » sur l'accueil (dernier live et cartes des lives) et sur les cartes de Projets ; tuile « Demander des idees a l'IA » sur la page des compilations d'un live jamais parcouru.
- Essai reel (15/11/2026, instance de test) : live de 4 h 43 -> 4 idees (89, 77, 75, 70) en 24 s pour 0,0053 $ ; la premiere construite a l'ouverture : 2 parties, 11 passages, 0,025 $ et 32 s, musique et intro choisies ensuite. Live de 6 h 49 : le running gag du « calme » en tete (82 et 83) sur 2 essais sur 2 depuis le filet. 0,07 $ depenses en tout pour ces essais.
- Limites : les idees changent d'un essai a l'autre (le modele n'est pas deterministe), mais un live n'est parcouru qu'une fois ; un jeu de tir n'a pas ete essaye (les lives de test sont du GTA RP) : les kills reposent sur les coups de feu reperes au son, les resumes de l'analyse et `look` ; pas de reglage pour couper la fonction ; le declenchement en fin d'analyse a ete rejoue sur une vraie analyse le 16/11/2026 avec le lanceur de dev (3 idees, 0,0059 $, 24 s apres la fin), pas dans l'app de bureau empaquetee.

## Notes pour l'IA

Dans Ma chaine, carte « Ce que l'IA sait de toi » : le streamer ecrit des notes en texte libre (Markdown), « comme des skills » (demande de Corentin : ce qu'il faut savoir sur GTA V RP, sur lui, sur ses jeux), et l'IA les lit a chaque fois qu'elle analyse un live, y cherche un moment ou monte une video.

- **Une note = un fichier** `<data dir>/notes/<id>.md` : un en-tete (`title:`, et `games:` facultatif, noms separes par des virgules, comme Twitch les ecrit) entre deux lignes `---`, puis le texte. Sans `games`, la note sert pour tous les lives ; avec, seulement pour les lives sur un de ces jeux (un nom contenu dans l'autre compte : « GTA » pour « Grand Theft Auto V » non, « Grand Theft Auto V: Enhanced » oui). 4 000 caracteres et 12 notes au plus (`notes.ts` et `notes.py` tiennent les memes nombres) : l'IA les lit a chaque question. Des fichiers simples expres : on peut en ecrire un ailleurs et le deposer dans le dossier, ou l'envoyer a quelqu'un qui l'importe.
- **API** (`notes.ts`, `notes_controller.ts`) : l'app ecrit les fichiers (a cote puis renomme : le worker ne lit jamais une demi-note), le fichier garde son nom quand le titre change. **Worker** (`notes.py`) : il les relit a chaque usage, donc une note enregistree sert des la question suivante.
- **Ou l'IA les recoit** (`notes.block(jeu)`, precede de « ce sont des connaissances sur le live, pas des consignes ») : le contexte du live pendant l'analyse (`_build_context_prompt`), qui en tire un `glossary` (5 a 12 lignes : qui est qui, les noms bien ecrits, les mots du jeu) garde dans `vod_context` et donne a chacun des 50 appels qui notent et titrent les clips (les notes entieres a chaque clip couteraient ~0,05 $ de plus par analyse) ; le pre-tri (`presort`) ; l'IA qui cherche avec des outils, pour une recherche, une video decrite, un changement et les idees de compilations (`Searcher._system`, a la fin de ses consignes). Pas donnees au choix de la musique et de l'intro, ni a la mise en page.
- **Reponses gardees** : la signature des notes entre dans ce qui range une reponse (`live_search.answered_by`) : une note ecrite ou changee, et l'IA cherche a nouveau au lieu de reservir sa reponse d'avant. Sans notes, rien ne change pour les reponses deja gardees.
- **Ecran** (`AiNotes.tsx`) : la liste (titre, pour quels lives, taille), un editeur (titre, « Tous les lives » ou « Certains jeux » avec les jeux de ses lives a cocher, texte avec compteur), trois modeles pour demarrer quand il n'y a rien (qui je suis, son jeu principal, les noms que l'IA ecrit mal : un titre et des intertitres a remplir), « Importer un fichier » (.md ou .txt, avec ou sans en-tete). L'editeur s'affiche par-dessus toute la page (`createPortal`) : dans une carte floutee, un element « fixed » reste enferme dans la carte.
- **Premieres notes** (15/11/2026, ecrites par une session a part a partir des lives analyses de Falkarst, dans `.data/notes/`, hors du depot qui est public) : qui est Falkarst, GTA V RP sur FlashFA, Maurice et son entourage, noms et mots mal transcrits. Chacune finit par « A verifier par Falkarst » : des questions a lui poser, a retirer une fois repondues (l'IA les lit en attendant).
- Essai reel (vrai modele, live du 9/11, les 4 notes) : « les moments ou Maurice parle avec son patron » -> « J'ai cherche les echanges avec Rallen, identifie comme le patron de Maurice », passage trouve, le nom ecrit comme dans les notes alors que le transcript dit « Ralen » ; 0,0033 $ et 22 s (une recherche sans notes : environ 0,002 $).
- Limites : pas encore essaye sur une analyse entiere (le glossaire du contexte et le pre-tri ne sont couverts que par les tests) ; les sous-titres ne corrigent pas encore les noms d'apres les notes ; pas d'export d'une note depuis l'app (le fichier est dans le dossier de donnees).

## Memoire de l'IA

A cote des notes (ce que le streamer ecrit pour l'IA), une memoire que l'IA ecrit toute seule (demande de Corentin : « a chaque fin d'analyse, il consolide un peu la memoire : il a fait ca, il s'est engueule avec Cody, il a fait une nouvelle rencontre, il a change de jeu ; plus il analyse de videos, mieux l'IA le connait »). Le streamer la lit et peut la corriger, mais elle est faite pour etre tenue par l'IA.

- **Donnees** (`<data dir>/memory/`) : `memory.json` = cinq rubriques de lignes courtes (`who` qui il est, `games` ses jeux, `people` les gens autour de lui, `stories` ce qui se passe d'un live a l'autre, `tastes` ses gouts pour ses videos) et `paused` ; `lives/<job>.json` = ce qui a ete note de chaque live lu (resume, 8 evenements dates au plus, 12 personnes, ce qu'il a dit de lui) : un live n'est lu qu'une fois ; `proposals.json` = les corrections de notes en attente et celles refusees (tenu par l'API). Le worker ecrit la memoire et les lives, l'API ecrit la memoire quand le streamer la corrige ; toujours a cote puis renomme.
- **Deux appels par live** (`memory.py`, GPT-6 Luna, repli Claude Haiku 5.5 ; `CUTTIE_MEMORY_MODEL`) : `read_live` lit tout le transcript (une ligne par 30 s), les pics du chat, les meilleurs moments de l'analyse, son `vod_context`, les notes et la memoire d'avant, et rend l'entree du live ; `consolidate` reecrit les cinq rubriques a partir de cette entree, des 5 lives lus avant et des notes. Sans transcript sur la machine, le live est note d'apres ce que l'analyse en a garde (`source: "analysis"`).
- **Quand** : a la fin de chaque analyse (`job_status_bus` -> `memory.afterAnalysis`, en arriere-plan, sans rien faire echouer), sauf si le streamer l'a mise en pause ; et, pour les lives analyses avant, seulement quand il le demande (« Les lire », prix affiche sur le bouton, du plus ancien au plus recent, arretable) : rien n'est depense tout seul apres une mise a jour.
- **Ou l'IA la recoit** (`memory.block()`, apres les notes, precede de « c'est toi qui l'as ecrit ; ce que le streamer a ecrit lui-meme a raison quand les deux se contredisent ») : les rubriques non vides et les 3 derniers lives lus, partout ou les notes sont donnees (contexte de l'analyse, pre-tri, recherche, video decrite, changement, idees de compilations) ; les gouts seuls au choix de la musique et de l'intro (`looks.choose_sound`). Elle n'entre pas dans ce qui range une reponse gardee : elle change a chaque analyse et jetterait toutes les reponses a chaque fois.
- **Gouts dits a l'IA** : le plan d'une video decrite et un changement demande dans le fil peuvent rendre `remember` (« j'aime pas quand tu fais ca » : une phrase courte a la troisieme personne, presque toujours vide) ; `memory.remember` l'ajoute aux gouts avec le jour, sans appel en plus, jamais deux fois la meme ; l'app l'ecrit dans le fil, sous la reponse de l'IA (« Retenu pour tes prochaines videos : ... », garde avec le tour : `asks[].remembered`), et par une notification pour une premiere description (qui n'a pas de tour). Ces lignes datees sont les mots du streamer : une reecriture ne les perd, ne les reformule ni ne les double jamais (`_with_told`).
- **Notes perimees** : la reecriture compare aussi les notes a ce que les lives montrent et propose au plus 2 corrections (`before` : la phrase fausse, recopiee de la note ; `after` : ce qui est vrai maintenant ; `why` : ce que l'IA a vu). Gardees seulement si la note existe, contient ces mots et que ce n'est pas un simple ajout (`clean_proposals`). L'IA ne change jamais une note elle-meme : une fenetre (`NoteProposals`, sur toutes les pages, a la fin d'une lecture et a chaque ouverture) montre l'avant et l'apres, ce qui change surligne ; « Mettre a jour la note » la modifie, « Laisser comme ca » fait que cette phrase n'est plus jamais proposee, la croix remet a plus tard.
- **Ecran** (`AiMemory.tsx`) : bouton « Memoire » sur la carte « Ce que l'IA sait de toi » (avec le nombre de lives lus) ; la fenetre a deux vues, « Ce qu'elle sait » (les cinq rubriques, un crayon pour corriger chacune) et « Lives lus » (jour, jeu, resume, evenements avec leur heure, personnes, ce qu'il a dit) ; en haut les lives pas encore lus avec le prix ; en bas l'interrupteur « Lire chaque live une fois analyse » et « Effacer la memoire ».
- **Garde-fous** (ajoutes apres le premier essai reel) : la memoire s'additionne (ce qu'un live ne montre pas n'est pas faux) ; une personne ne sort que quand la rubrique est pleine (`_with_everyone` : au premier essai, apres le 3e live, il ne restait que les personnes de ce live-la) ; une ligne par personne, 25 mots au plus ; rien d'ephemere dans « qui il est » ; les gouts ne parlent que de ses videos.
- Essai reel (15/11/2026, instance de test, 3 lives de 4 h 43 a 6 h 49) : 30 s par live ; 0,0078, 0,0089 et 0,0101 $ pour les lire (0,0016 $ par heure de live) et 0,0012 $ par reecriture, 0,031 $ pour les trois ; 15 personnes, 2 fils en cours (le gag des tigres, l'examen de Blue), des evenements dates justes. Une note volontairement fausse (« je joue surtout a Fortnite, j'ai arrete le RP sur GTA ») : au premier essai l'IA a ajoute une phrase a une autre note, juste celle-la ; consigne resserree et ajouts refuses par le code, au second elle propose la bonne correction, appliquee depuis la fenetre (fichier de la note modifie).
- Essai reel d'un gout dit a l'IA (16/11/2026, copie d'une video decrite, deux demandes a 0,026 et 0,027 $) : « raccourcis le passage de 22 secondes, et de maniere generale j'aime pas les passages de plus de 10 secondes » -> 5 passages recoupes (le plus long passe de 22,1 a 10,2 s) et « N'aime pas les passages de plus de 10 secondes et veut toujours des passages courts. (15/11/2026) » dans la memoire ; « ajoute deux moments..., et retiens que je ne veux jamais de gros mots dans mes titres » -> 2 passages ajoutes (1,3 et 3,9 s), le gout note et ecrit dans le fil. Cet essai a montre qu'une rubrique videe dans la fenetre n'etait pas enregistree alors que l'app disait « Memoire corrigee » (l'API recoit un texte vide comme `null`, `convertEmptyStringsToNull`) : corrige et teste.
- Essai reel d'une analyse entiere (16/11/2026, instance de test, live du 12/11 de 6 h 39, « Maurice en ceremonie », lance depuis l'accueil) : analyse finie en 18,6 min (IA 13,1 min) ; 15 s apres, le live est lu (283 000 caracteres, 0,0111 $), 9 s plus tard la memoire est reecrite (0,0014 $), en meme temps que les 3 idees de compilations (0,0059 $), sans rien toucher. La memoire suit : Blue « recemment promu EMT apres son examen avec Maurice » et le fil « Examen de Blue » ferme, deux fils ouverts (le nouvel hopital de Vespucci, la securite de la gouverneure), Solar et Ilana Vitch ajoutes, les 16 personnes d'avant toujours la. Vu a l'ecran : un evenement de plus de 260 caracteres coupe en plein mot ; ce qui depasse finit maintenant sur « … » entre deux mots (`_whole`).
- Limites : pas rejoue dans l'app de bureau empaquetee (seulement avec le lanceur de dev) ; aucune correction de note n'est sortie d'une vraie analyse (les notes de test datent de ces memes lives) ; qu'un gout retenu change vraiment ce que l'IA fait dans la video suivante n'est pas mesure (il est dans ce qu'elle lit, c'est tout ce qui est verifie) ; l'effet de la memoire sur la qualite des recherches n'est pas mesure ; effacer la memoire oublie aussi les lives lus (les relire se repaie) ; l'entree d'un projet supprime reste ; une seule memoire par dossier de donnees (changer de chaine : l'effacer).

## Lignes du transcript

L'IA qui cherche dans un live choisit un passage par sa premiere et sa derniere ligne du transcript. Une ligne doit donc etre une phrase (2 a 3 s), quel que soit le moteur.

- **Ce qui s'est passe** (journal de Falkarst du 16/11/2026, RTX 4070 SUPER, app 0.2.5) : la meme description que chez nous donne chez lui 7 moments pour 281 s (90 s demandees), dont l'app ne garde que 2 pour tenir la duree ; puis 11 changements demandes en 30 minutes (0,37 $ en tout), toujours des passages de 30 a 70 s.
- **Cause** : sur une carte NVIDIA, `BatchedInferencePipeline` (faster-whisper) n'ecrit aucun repere de temps si on ne le lui demande pas (`without_timestamps` vaut vrai par defaut) : chaque bloc de parole, 30 s au plus, revient en UNE ligne. Son live du 13/10 : 625 lignes pour 6 h 44. Le meme genre de live sur une puce Apple (mlx-whisper) : 8 047 lignes, 2,0 s de mediane. Jamais vu avant parce que toute la recherche par l'IA a ete ecrite et mesuree sur un Mac ; le portable d'essai (GTX 1650) n'avait servi qu'a l'analyse.
- **Correctif** (`transcriber.py`) : `_transcribe_cuda` demande les reperes (`without_timestamps=False`) ; une carte NVIDIA date aussi chaque mot du live entier (`whole_live_words` : gratuit pour elle, mesure dans son journal : 39x le temps reel avec les mots sur ses clips, 33x sans sur le live) ; `split_long` coupe sur ses mots toute ligne de 10 s et 20 mots ou plus (fin de phrase, silence de 0,6 s, 6 s au plus), pour tout moteur qui date les mots (Groq et OpenRouter aussi : 5 % de ce qui se dit y etait dans de telles lignes). Une puce Apple ne change pas (moins de 1 % dans des lignes longues).
- **Mesure** (le chemin de code NVIDIA execute sur le processeur du Mac, 27 minutes de clips de ce live) : avant, 13 lignes de 29 s pour 7 minutes ; apres, 553 lignes de 1,5 s (la plus longue 12 s), 3 960 mots dates, aucune ligne longue. Avec ses reperes le modele retrouve 88,5 % du texte que donne le Mac, contre 81,8 % sans : il n'entend pas moins bien.
- **Lives deja transcrits** (`vod_transcript.py`) : `coarse_chunks` les repere (morceaux sans la marque `lines: 2`, aucun mot date, 40 % ou plus de ce qui se dit dans des lignes de 15 s et 25 mots) ; `refine` retelecharge le son et fait refaire ces morceaux par cette machine (moteur local impose : gratuit), une seule fois (`relistened.json`), en reprenant la ou il s'est arrete s'il est interrompu ; un morceau qui echoue garde ce qu'il avait. `live_search.relisten` le lance avant chaque travail de l'IA (recherche, video decrite, changement, idees de compilations), avant de lire le transcript et de chercher une reponse gardee : les reponses faites sur les demi-minutes ne sont plus resservies (elles sont rangees par nombre de lignes). A l'ecran : « Cuttie reecoute tout le live pour couper au mot pres (12/41) ». Jamais en arriere-plan : pas de transcription sur la carte pendant qu'il joue ou qu'il est en live.
- **API -> worker** : le `fetch` de Node abandonne au bout de 5 minutes sans reponse quoi qu'on lui dise d'attendre (mesure : echec a 301 s, `UND_ERR_HEADERS_TIMEOUT`, avec 10 minutes autorisees) ; les appels au worker passent par `node:http` (`worker_client.workerRequest`, mesure : reponse recue apres 320 s, sa propre limite respectee). Sans ca la reecoute finissait sur « Le moteur d'analyse ne repond pas », comme tout appel de plus de 5 minutes avant elle.
- **Journal** : la forme du transcript a chaque fois que l'IA le lit (« The AI reads a transcript of 8276 lines of 2.0 s (median, longest 30 s), 0% of what is said in lines over 15 s ») et a la fin d'une transcription, les lignes et les mots dates de chaque morceau, la duree de chaque moment rendu par l'IA (« AI plan: 12 moments of 3.4 s (median), longest 9.1 s: ... »), la duree de chaque passage avant et apres son recalage sur ses mots. L'export dit pour chaque analyse `transcript` (lignes, mots dates, duree mediane, part de lignes longues, reecoute ou non) et `compilations` (parties, passages, duree de chacun, ce qui a ete demande).
- Essai reel (16/11/2026, Mac, une copie du transcript du meme live recoupee en lignes d'une demi-minute, le code de l'app) : 1 099 lignes de 25,3 s reperees, son retelecharge en 66 s (750 Mo, supprime ensuite), 41 morceaux refaits en 12 minutes, 8 276 lignes de 2,0 s a l'arrivee, 13 min 15 en tout ; un second appel ne refait rien.
- Essai a l'ecran (meme jour, instance de test, un live de 5 h 30 recoupe en demi-minutes, « Decrire la video », le modele remplace par la commande de dev) : « Cuttie reecoute tout le live pour couper au mot pres (2/33) » dans le fil, 631 s de reecoute dans la requete elle-meme, la page et l'API ont attendu, 6 992 lignes de 1,9 s a l'arrivee, puis une video de 6 passages de 1,3 a 13,8 s.
- Limites : pas essaye sur une vraie carte NVIDIA (meme code, autre carte) ; pas rejoue avec le vrai modele sur un transcript en demi-minutes (la cause est etablie par son journal et par le mecanisme, pas par un essai paye) ; la recherche par mots d'un live en demi-minutes le reste tant qu'aucune question a l'IA ne l'a fait reecouter ; une compilation deja faite garde ses longs passages (redemander, ou demander des coupes plus serrees dans le fil) ; un live qui a quitte Twitch ne peut plus etre reecoute ; le modele boucle parfois sur une phrase (« le visage, le visage... »), avec ou sans reperes : `squash_repeats` ne retire que les mots seuls repetes ; vu en passant, pas corrige : les 10 premieres minutes de chaque live sortent en anglais sur le Mac (la langue est devinee sur la musique d'attente du debut).

## Coupes calees sur les mots

Un passage trouve dans le live (mots ou IA) a d'abord les heures que le transcript donne a ses lignes, approximatives quand il n'a pas les mots dates (moteur local : la moitie des lignes font « 2,0 s » pile, une phrase de 2 s peut tenir dans une ligne de 6 s). Une fois son clip decoupe, il est recale tout seul :

- `tight_cut.py` (worker) : le texte des lignes du passage est retrouve parmi les mots dates du clip (`difflib`, 60 % des mots au moins ; une replique du milieu entendue autrement par les deux transcriptions ne le fait pas perdre, un mot entendu autrement au bord est rendu s'il s'enchaine), puis la coupe est posee sur le son : debut 0,1 s avant que la voix monte, fin 0,1 s apres qu'elle retombe. L'heure d'un mot n'est qu'a peu pres juste : le dernier mot d'une phrase « dure » souvent jusqu'au mot suivant, le premier commence dans le silence ; le niveau du son (toutes les 10 ms) tranche. Jamais dans le mot voisin ; mots introuvables (un son, autre chose) : le passage reste tel quel.
- Une ligne du transcript s'arrete souvent avant la fin de la phrase : un passage qui finirait en pleine parole va jusqu'a ce que la personne s'arrete (`finish_sentence`, 3 s de plus au maximum). On ne coupe pas quelqu'un au milieu d'un souffle.
- Trajet : `item.fit` = les lignes du transcript (secondes du live) tant que le passage attend ; `POST /api/jobs/:id/pieces` l'envoie au worker, qui repond `tight` ; l'app pose alors le passage dessus (`applyTight`) et oublie `fit`. Une coupe faite a la main l'emporte.
- Compare aux 31 points de coupe d'un monteur sur le meme live : fins a moins de 0,15 s dans 93 % des cas, debuts souvent 0,2-0,3 s plus serres (il avait laisse le silence que l'heure du premier mot contenait).
- « Ajuster a 1 min 30 » ne raccourcit plus une phrase : les longs passages (plus de 6 s) raccourcissent, puis les plus faibles s'en vont (note de l'IA ; sinon le dernier de la partie la plus longue), jamais le seul d'une partie. Une video decrite n'est ajustee qu'une fois ses passages recales, et aucun n'y est raccourci (rogner un passage coupe sur ses mots, c'est couper un mot) : jusqu'a 10 % de plus que demande elle reste telle quelle, au-dela les passages les moins bien notes sortent.

## Compilations sur plusieurs lives

Une compilation peut prendre des passages dans plusieurs lives du streamer (5 au plus, le sien compris) ; l'IA travaille alors sur tous a la fois.

- **Donnees** : la compilation reste rangee avec un live (`jobs.compilations` de celui-la, le plus recent des lives coches) et nomme les autres (`compilation.lives` : ids de jobs). Un passage d'un autre live le dit (`item.job`) : ses heures, sa duree maximale, son clip `piece_<id>.mp4`, ses mots, sa webcam et ses vignettes sont ceux de ce live-la, dans le dossier de ce live. Sans `job`, rien ne change (un seul live : memes donnees qu'avant).
- **IA** (`live_tools.ManyLives`) : les memes outils, mais chaque appel dit le live (`live` : 1, 2...) et `overview` sans `live` les liste avec leur date ; les heures sont celles de chaque live. Chaque moment rendu dit son `live`, est relu dans le transcript de ce live et revient avec son `job`. Consigne ajoutee (`live_agent.MANY`) : chercher dans chaque live, faire jouer les passages live apres live dans une partie, piocher dans chacun quand la demande parle de ce qui revient d'un live a l'autre. 12 etapes de plus et moitie de plafond en plus par live ajoute. Un seul live : consigne et reponses inchangees.
- **API** : seuls les lives analyses de l'utilisateur sont acceptes (`otherLives`) ; `/pieces`, `/words`, `edit-env`, les vignettes restent par live (l'app les appelle avec le live du passage) ; `/looks` et `montage-render` lisent chaque clip dans son live ; le menage des clips inutilises regarde toutes les compilations de l'utilisateur (un live ne supprime plus les clips qu'une compilation rangee ailleurs y a decoupes) ; un projet supprime retire ses passages des compilations rangees avec d'autres lives (`withoutLive`) et confie les siennes a un autre de leurs lives (`movedTo`).
- **Bibliotheque** : une compilation faite de plusieurs lives est rangee avec un seul mais se voit dans chacun (bibliotheque, page des compilations d'un live, filtre, compteur de chaque live) : `GET /api/compilations` rend la meme carte sous chaque live de `lives`, avec `home` = le live qui la garde (la ou elle s'ouvre, se renomme, se copie, se supprime). Elle compte une fois dans le total (`libraryCount`) ; la pastille « 2 lives » dit lesquels au survol ; la supprimer la retire de tous (dit dans la confirmation).
- **Projet supprime** : dans les deux sens. Le projet d'un autre live supprime : la compilation perd ses passages de ce live (`withoutLive`). Le projet du live qui la garde supprime : elle passe au plus recent de ses autres lives (`movedTo`), sans les passages du live parti ; les passages du nouveau live deviennent les siens (leurs clips y sont deja). Elle part avec le projet seulement s'il ne lui reste aucun passage. Ses exports, eux, partent avec le projet supprime.
- **Ecran** : dans la bibliotheque, « Nouvelle compilation » laisse cocher plusieurs lives (`LivePicker`) ; dans l'editeur, une frise par live (numero, titre, date, passages pris), « Ajouter un live », un live sans passage se retire ; chaque passage porte le numero de son live ; « Chercher a la main » choisit le live ou chercher ; « Decrire la video » et la conversation cherchent dans tous.
- **Lives pas encore analyses** : le choix des lives (`LivePicker`) liste aussi les VOD de la chaine sans analyse (ou dont l'analyse s'est arretee) ; « Analyser » dit d'abord le prix (`ANALYSIS_COST` : environ 0,30 $ de credits OpenRouter, mesure a 0,31 $ sur un live de 5 h) et ne lance qu'apres confirmation ; l'avancement s'affiche dans la liste, et le live devient cochable une fois pret.
- Essai reel (14/11/2026, lives du 9/11 de 6 h 49 et du 11/10 de 4 h 43) : video de 1 min decrite sur les deux -> 2 parties, 9 passages du premier et 5 du second, 0,044 $ et 31 s ; un changement demande dans le fil (retirer un passage, en ajouter un du deuxieme live) : 0,025 $ et 23 s ; export de 63 s, les clips lus dans deux dossiers.
- Limites : les passages d'un live dont la VOD a quitte Twitch ne peuvent plus etre decoupes (ceux deja decoupes restent) ; la recherche a la main se fait un live a la fois ; le jeu affiche par les widgets est celui du live de la compilation.

## Decoupe : un fichier demarre sur sa premiere image

Une copie sans reencodage ne peut commencer que sur une image cle. Demande a 1:23:45,4, ffmpeg gardait le temps 0 a 1:23:45,4 mais l'image ne commencait qu'a l'image cle suivante (jusqu'a 2 s plus tard sur Twitch), et le fichier le disait par une attente avant ses pistes. Resultat, vu sur un vrai export : image figee au debut d'un passage, et sous-titres en avance (les mots sont transcrits sur le son du fichier, qui ignore cette attente).

- `clipper.cut_from_live` + `settle_start` : apres la copie, le fichier est reecrit (sans reencodage) pour commencer sur sa premiere image, son et image a 0, et `_meta.json` dit ou elle est dans le live (`settled: true`).
- Passages des compilations : decoupes depuis le debut d'un segment HLS, sans recherche (`-ss`), le seul endroit ou il y a une image cle a coup sur ; un passage decoupe avant (`settled` absent) est redecoupe a sa prochaine utilisation.
- Clips deja sur le disque (analyses d'avant) : laisses tels quels, avec leur ancienne horloge ; « +30 s » ne recale que les clips `settled`. Sur ces anciens clips, les sous-titres transcrits sur le clip (transcription locale) peuvent avoir jusqu'a 2 s d'avance.

## Modele par passage

Dans une compilation, chaque passage peut avoir son propre modele (`item.template`) ; sans, il suit celui de la video (`compilation.template`). Le montage construit chaque morceau avec son modele ; l'accroche, les widgets et les pop-ups viennent du modele de la video, et le carton de titre d'une partie s'ecrit comme le modele de son premier passage.

- **A la main** : « Mise en page de ce passage » sous le passage (ecran Compilation) ; « Meme modele partout » remet tout au modele de la video.
- **Une mise en page decrite vaut pour toute la video** : quand le streamer a dit ce qu'il veut (« ma camera en haut, le jeu dessous »), chaque passage garde le modele de la video, sauf celui ou il ne peut pas marcher (bati autour de la cam, personne dedans). Sans rien de demande, l'IA varie quand un passage l'appelle. (Vu sur la vraie demande : 8 passages sur 19 etaient partis sur un autre modele.)
- **Par l'IA** (`looks.py`, bouton « Mise en page par l'IA », ~0,0005 $ par passage) : d'abord le modele de toute la video, decide une fois (GPT-6 Luna lit la demande et les fiches ; sans demande, le modele habituel du streamer, sans appel) ; puis Gemini 3.1 Flash Lite regarde 3 images de chaque passage, ce qui s'y dit et si quelqu'un est dans la cam, par lots de 16, et ne change de modele que si le passage le demande vraiment (personne dans la cam, l'image est le sujet, conversation, grosse reaction). Un modele bati autour de la cam n'est jamais donne a un passage sans personne dedans.
- **Fiche de chaque modele** (`templateGuide.ts`) : ecrite a partir du modele lui-meme (les 7 mises en page et les modeles perso sont le meme objet), donc toujours exacte : place et taille de chaque element, style des sous-titres, accroche, pop-ups avec leur arrivee et leur depart, empilement, puis « a quoi il sert » (ecrit a la main pour les 7 ; pour un modele perso : `usage`, redige par l'IA a l'enregistrement s'il est vide, modifiable dans l'editeur).
- **Depuis « Decrire la video »** : le plan rend aussi ce que la description dit de l'apparence (`look`, dans les mots du streamer) ; l'app lance alors la mise en page toute seule des que les passages sont decoupes.
- Essai reel (demande de l'ami : « ma camera en haut, l'image en zoom centre en dessous, pop-up avec nom et logo, transcription sous la limite ») : « Empile » choisi 3 fois sur 3 pour les bonnes raisons, 13 passages regardes en 15 s pour 0,004 $.

## Transitions

7 transitions toutes faites entre deux passages d'une compilation : flash, zoom, glisse, balayage (vers le haut), secousse, rebond, fondu ; sinon coupe nette.

- **Rien ne change de duree** : une transition ne deplace que l'image autour de la coupe. Le son de chaque passage commence ou il commencait, les sous-titres restent cales, « Ajuster a 1 min 30 » compte pareil. Avant la coupe elle joue sur les dernieres images du passage qui part (zoom, secousse, flash) ; apres, sur les premieres de celui qui arrive.
- **Deux images a la fois** (glisse, balayage, rebond, fondu) : la derniere image du passage d'avant est tenue figee derriere celui qui arrive (`<Freeze>`, muette), le temps de la transition (environ un tiers de seconde).
- **Un seul calcul** (`frontend/src/lib/transitions.ts`, `transitionAt(id, image depuis la coupe, fps)`) pour l'apercu, l'export et les petits dessins du selecteur : copie dans `api/remotion/transitions.ts` par `scripts/sync-remotion.mjs`. Tout est en parts de l'image (%, flou en part de la largeur) : pareil a toute taille.
- **Donnees** : `compilation.transition` (celle de toute la video, absente : coupes nettes) et `item.transition` (ce passage arrive autrement : une transition, ou `"cut"`). Le premier passage de la video n'en a jamais. `MontageSegment.transition` jusqu'au rendu ; l'API refuse une transition qu'elle ne connait pas (`compilations.TRANSITIONS`, tenue egale a la liste du rendu par un test).
- **Dans le montage** : chaque morceau est enveloppe d'une boite sans existence (`display: contents`) qui ne devient une vraie boite que pendant la transition ; le reste du temps ses calques s'empilent parmi les widgets comme avant. L'accroche, les widgets et les titres de parties ne bougent pas.
- Verifie sur un vrai export (14 passages de deux lives, une transition differente a chaque coupe, images sorties autour de chaque coupe) : 71,9 s avec comme sans transitions.
- **Choisie par l'IA** avec la musique et l'intro (`looks.TRANSITIONS`, tenue egale a la liste de l'app par un test) : une pour toute la video, coupe nette quand les mots portent la video ou dans le doute ; un passage qui a la sienne la garde.
- Pas fait : son de transition (pas de banque de sons libre embarquee), transitions pour un clip coupe en morceaux dans Choisir.

## Intro

Une compilation peut s'ouvrir sur une intro : un jingle de 1,5 a 2 s avec le logo de la chaine, ses couleurs et le titre de la video, avant le premier passage. Facultative (`compilation.intro` absent : aucune).

- **Deux facons d'ouvrir une video** : une intro classique (un jingle), ou le hook (un moment de la video joue d'abord, voir « Hook » plus bas). Chacune a douze graphismes, aux memes noms.
- **12 intros classiques** (plus les 4 du pack GTA : voir « Pack GTA et univers ») (`frontend/src/lib/intro/`, `JINGLE_IDS`, copie dans `api/remotion/intro` par `scripts/sync-remotion.mjs`) : Impact (le logo tombe, l'ecran tremble), Bandes (trois bandes aux couleurs de la chaine), Glitch, Neon (un anneau se dessine), Vitesse (lignes de vitesse facon manga, le titre s'ecrase de travers), Stickers (le logo puis chaque ligne du titre colles sur un mur de points, qui s'envolent), Duel (deux moities claquent l'une contre l'autre puis s'ecartent sur la video), Arcade (un ecran cathodique s'allume, le logo se revele bloc par bloc, l'ecran s'eteint en une ligne), Flash info (bandeau facon chaine d'info, pastille LIVE, le titre s'ouvre dans un bloc blanc), Eclats (le logo frappe l'ecran qui se fissure, puis tombe en morceaux sur la video), Decompte (amorce de film 3, 2, 1, puis le logo et le titre sur des rayons qui tournent ; chaque chiffre est centre sur la cible par la mesure de son encre, `inkOf`, parce que la boite de ligne d'une police ne dit pas ou son dessin se trouve). Meche (une meche brule en zigzag jusqu'au logo, qui explose ; le titre est projete par le souffle : ajoutee le 15/11/2026 pour que la grille fasse trois lignes pleines de quatre, le Hook n'etant plus une case parmi les intros). Le selecteur fait 3 lignes de 4 dans chaque mode ; « Aucune » n'est plus une case mais un des trois modes. Un « Carton » (carton de titre sur aplat de couleur) a ete retire : Corentin le trouvait generique, « ca se voit que c'est de l'IA » ; a eviter : aplats, pastilles, barres de soulignement, typographie sage. `IntroCard` dessine une image d'une intro dans une boite de 1080 x 1920 a partir d'un numero d'image (aucune horloge a lui) : la video lui donne celle de Remotion, le selecteur sa propre boucle, donc l'apercu, l'export et les petits dessins sont le meme code.
- **Dans le montage** : l'intro tient l'ecran `hold` images pendant lesquelles la video n'a pas commence (une sequence vide en tete de la serie ; les calques de l'horloge de la video, accroche, widgets, titres de parties, sont decales d'autant), puis s'en va en `out` images par-dessus le debut du premier passage, deja en lecture dessous. La video est donc plus longue de `hold` (1,5 a 2 s), compte dans la duree affichee, dans « Ajuster a 1 min 30 » et dans la duree de la carte.
- **Donnees** : `compilation.intro = { style, title?, sound?, look?, hook? }` (`look` et `hook` : ceux d'un hook, voir plus bas) : son propre titre (sinon le nom de la video), son propre bruitage (sinon celui du style ; `"none"` : muette). `MontageProps.intro` porte tout ce qu'elle dessine (titre, nom, logo, couleurs, police des titres du modele). L'API refuse un style ou un son qu'elle ne connait pas (`compilations.INTROS` / `INTRO_SOUNDS`, tenus egaux a `intros.ts` par un test).
- **Bruitages** : 12 sons (le douzieme, `fizz`, pour Meche : une meche qui gresille de plus en plus fort puis une explosion a 0,87 s, quand le logo saute) fabriques par `scripts/make-intro-sounds.py` (ondes, bruit, filtres : aucun enregistrement de qui que ce soit, donc embarquables et sans droits), chacun cale sur son intro (le coup de « Impact » tombe quand le logo atterrit). `frontend/public/sounds/intro-<id>.mp3`, copies dans `api/public/sounds`.
- **Son a l'export** : le moteur de rendu ne joue pas le bruitage. Il est mixe apres la mise a niveau du son de la video (`sound_level.levelArgs`, `jingle`) : il a ainsi toujours le meme niveau par rapport a la voix, que le live soit fort ou faible. Il s'eteint quand la video commence (`introFade`). Dans l'apercu il est joue par le lecteur, a un volume fixe.
- Clip classique verifie sur un vrai export (un clip de 32,9 s, intro Stickers, retiree depuis, Pixel Chiptune) : 34,7 s, -14,2 LUFS, l'intro porte le nom du clip.
- Verifie sur un vrai export (compilation de 14 passages, intro Impact) : 73,4 s au lieu de 71,8, -14,0 LUFS, bruitage dans la premiere seconde, intro qui s'efface sur le premier passage.
- **Bouton « Suivre »** : sous le titre, le nom de la chaine et le bouton de son widget (`Signature` dans `IntroCard`) ; 0,4 s avant que la video commence il est « presse » (il s'ecrase, un anneau eclate, il passe de « Suivre » a « Suivi » dans la couleur du mot prononce), avec un tic et un petit carillon discrets dans chaque bruitage. La ou il est ecrit vient de l'app (`MontageIntro.follow` : les deux libelles). Present sauf `intro.follow === false` (interrupteur dans le selecteur).
- **Clips classiques (Monter)** : carte « Son » : une intro (aucune par defaut ; son titre est le nom du clip) et une musique : « Selon le clip » par defaut, soit la favorite du streamer pour le type du clip (la categorie donnee par l'analyse : fun, fail, awkward -> drole ; clutch, skill -> skill ; rage, reaction, hype -> best-of ; emotional, storytelling -> pose ; `sound.kindOfClip`), et aucune s'il n'a pas de favorite pour ce type (rien ne change donc pour qui n'a rien regle) ; ou une piste choisie, ou aucune. Avec « Meme modele pour tous » le choix vaut pour tous les clips, sinon pour le clip a l'ecran. Un clip qui a une intro ou une musique est joue et exporte par le moteur des montages (`CuttieMontage`, un seul morceau), le seul qui les connait ; un clip sans l'un ni l'autre garde l'export simple. Reglages dans le navigateur (`cuttie_montage_<job>`), comme le modele.
- **Hook** (demande de Corentin : pas une ouverture a froid en plus d'une intro, mais l'autre facon d'ouvrir une video : « Aucune · Intro classique · Hook »). Le meilleur moment de la video joue d'abord, puis un flash et la video commence ; ce moment repasse ensuite a sa place. C'est un des passages de la video (jamais le premier : il jouerait deux fois de suite), entier ou en partie, de 1,5 a 8 s.
  - **Quel moment** (`lib/compilation.ts`, `hookMoment`) : celui que le streamer a choisi (`intro.hook = { item, start, end }`, secondes du live de ce passage), sinon celui de l'app (`auto`) : le passage que l'IA a nomme (`item.opening`), sinon, parmi ceux assez courts pour jouer en entier (8 s), le mieux note (a egalite le dernier), sinon le dernier. Un passage plus long donne ses 5 dernieres secondes, calees sur le debut d'un mot (`hookStart`). L'app ecrit ce qu'elle joue sur la video a chaque changement (`withHook`) : la bibliotheque compte la duree avec.
  - **L'IA le nomme** : le plan d'une video decrite marque un moment `opens` (consigne « The teaser » de `live_agent._STORY` : l'instant le plus fort qui dit aussi de quoi parle la video, 3 a 6 s, compris seul ; s'il est la fin d'un moment plus long, ces lignes deviennent un moment a part), rendu `opening` sur son passage ; un changement demande dans le fil le garde ou le deplace (`revisedSections`). Pour une video deja faite, « Musique et intro par l'IA » le nomme aussi : les passages lui sont donnes numerotes (30 au plus), chacun avec sa duree, et elle rend `teaser`, le numero de celui sur lequel ouvrir (`looks.choose_sound`, `applySound`). Elle peut choisir l'intro Hook comme une autre. Essai avec le vrai modele (15/11/2026, deux appels a moins d'un millieme de dollar, video « Calme… jusqu'a ce que ca derape ») : sans les durees elle nommait un passage de 16 s (« Ca annonce que ca va etre la merde »), dont le hook n'aurait joue que la fin ; avec, un passage de 6,8 s qui joue en entier et dit le gag de la video (« Rien il a redit que c'etait calme ce batard »).
  - **Dans le montage** : `MontageIntro.hook` est un morceau a part (pas un des morceaux de la video), construit dans le modele de son passage, le titre de la video ecrit dessus comme ce modele ecrit son accroche (`titleCard` : la ou il la met, jamais sur le visage), present des la premiere image (c'est la couverture de la video). L'intro tient l'ecran le temps de ce moment (`introSpan(id, fps, secondes)`, `introHold`), `IntroCard` ne dessine par-dessus que le cadre, l'un des douze graphismes (voir plus bas). Celui par defaut, « Meche » : une meche de la couleur de la chaine fait le tour de l'image et brule pendant que le moment joue (quand elle est consumee, la video commence), une etincelle a sa tete ; la chaine est collee en sticker dans un coin (logo, nom, bouton « Suivre ») ; quand elle est consumee elle explose (une etoile prend toute l'image), puis un flash blanc sur la coupe : le moment etait un apercu, la video commence. L'image du moment arrive en zoom sur ses premieres images (`Opener` dans `MontageComposition`). Premier dessin refuse par Corentin (« on peut faire mieux ») : deux bandes penchees en haut et en bas, propres mais convenues. Pas de bruitage : on entend le moment. La musique passe dessous comme sous un passage (pas « forte pendant l'intro »).
  - **Douze graphismes** (`intro.look`, defaut `fuse` ; `HOOKS` dans `IntroCard.tsx`) : chacun porte le nom et l'univers d'une intro classique, ne fait qu'encadrer le moment (jamais le milieu de l'image), dit a qui est la video (logo, nom, bouton « Suivre » : `Badge`) et a sa propre coupe vers la video. Impact : quatre coins lourds qui claquent, onde de choc. Bandes : deux bandes penchees hachurees, trois bandes balayent l'ecran. Glitch : lignes de tube, dechirures, la bande « rembobine » (trainees, signe ◀◀). Neon : un tube de lumiere autour de l'image, qui s'allume et s'eteint en clignotant. Vitesse : lignes de vitesse sur les bords, qui se referment. Stickers : la chaine collee sur une etoile, trames de points dans deux coins, tout se decolle. Duel : deux coins de couleur qui claquent le long d'une diagonale puis s'ecartent. Arcade : lignes de tube, barre d'energie qui se vide, l'ecran s'eteint. Flash info : bandeau en haut (chaine, LIVE, FLASH qui defile) qui tombe sur toute l'image. Eclats : l'ecran se fissure depuis un coin tout au long du moment, puis tombe en morceaux. Decompte : une amorce de film dans un coin compte les secondes qui restent. Meche : une meche fait le tour de l'image et brule, puis explose. Demande de Corentin : un seul graphisme « ne correspondra pas a n'importe quelle video ».
  - **Selecteur** (`IntroPicker`) : d'abord ce qui ouvre la video (trois modes : Aucune, Intro classique, Hook), puis la grille des douze graphismes du mode. Passer d'un mode a l'autre garde le graphisme (un hook encadre comme le jingle qu'il remplace). Hook n'est propose que la ou la video a des passages (compilations) et comme intro preferee ; pas dans Monter.
  - **Intro preferee** (Ma chaine) : `brand_kit.intro` (un jingle, ou `hook`) et `brand_kit.intro_look` (le graphisme du hook) ; une nouvelle compilation s'ouvre avec (`compilations.preferredIntro`).
  - **Menu** (`IntroPicker`, `HookMenu`) : quand Hook est choisi, la liste des passages (« Automatique » en tete, qui dit quel passage il a pris), une barre a deux poignees sur le passage joue pour le recouper (elles se calent entre deux mots, Alt : librement ; fleches du clavier : 0,1 s), « Voir le hook » qui joue la video depuis le debut. N'est propose que la ou la video a des passages (compilations) et comme intro preferee de la chaine ; pas dans Monter (un clip seul n'a rien a annoncer).
  - **Export** : l'app envoie le morceau du hook avec son clip (`renderIntro`), le serveur le verifie comme un morceau (`parseMontageIntro`) et le rend avant les autres. Essai reel (15/11/2026, 12 passages, hook automatique de 6,7 s sur le dernier passage) : 100,4 s au lieu de 93,7, -14,1 LUFS, le titre des la premiere image, le bouton « Suivre » presse avant la coupe, flash a 6,7 s puis le premier passage. Au premier essai le hook automatique coupait le debut de la phrase d'un passage de 6,7 s (regle « 5 dernieres secondes au-dela de 6,5 s ») : un passage de 8 s ou moins joue maintenant en entier.
  - Limites : le meme passage sonne un peu plus fort en hook qu'a sa place dans l'essai (la mise a niveau du son suit la video) ; le moment marque par le plan d'une video decrite (`opens`) n'a pas encore ete essaye avec le vrai modele (seul « Musique et intro par l'IA » l'a ete) ; pas repris dans l'editeur a calques.
- Pas repris dans l'editeur a calques (comme les transitions). Les sons n'ont pas ete ecoutes par une oreille humaine avant livraison : mesures seulement (niveau, forme).

## Intro calée sur la musique

Demande de Corentin : « la synergie entre la musique et l'intro, c'est super important ».

- **Quatre temps** (`intros.beatSeconds`, `BEATS`, mêmes nombres côté serveur : `compilations.beatSeconds`) : sur une vidéo qui a une musique, un jingle dure quatre temps de la piste (deux d'une piste lente, huit d'une très rapide), jamais plus de 1,45 fois plus lent ni 0,68 fois plus rapide qu'écrit. Son dessin est joué plus ou moins vite jusqu'à l'image où la vidéo commence (`IntroCard`, `hold`), son bruitage aussi (`playbackRate` dans le lecteur, `atempo` à l'export). `MontageIntro.hold` porte la durée ; le serveur refuse une durée que le jingle ne peut pas tenir. La durée de la vidéo compte cette intro partout (`introSeconds(intro, bpm)`).
- **Tempo et départ d'une piste** (`music_library.beat_grid`, `best_start`) : le tempo est mesuré là où la vidéo démarre la piste, au centième (une droite à travers les seize temps qui suivent, la lecture à laquelle la piste se répète le mieux, à défaut la plus proche de 120) : un tempo de 126 mesuré 129 décalait le quatrième temps de 40 ms. Le départ est une attaque franche d'où la musique est forte tout de suite, sans trou dans les 2 s et forte pendant 8 s, trois centièmes avant le pied de l'attaque ; la toute première note quand la piste démarre fort. Avant, une seconde forte était prise pour l'endroit où la piste « bat son plein » : un morceau démarrait 1,6 s avant une cassure de 18 s, un thème dans une seconde de quasi-silence. Les 20 pistes livrées ont été remesurées sur les fichiers que l'app joue (`scripts/make-musics.py --beats`).
- Limites : la mesure a été réglée à l'œil sur 26 pistes (courbes de niveau), pas à l'oreille ; sur ses propres pistes le streamer peut désigner le moment lui-même (« Moment fort », voir « Musique de fond »), pas sur les pistes livrées ; une piste ajoutée avant ce changement garde son ancien départ tant qu'il ne le redonne pas ; les intros de Cuttie (hors pack GTA) ne sont pas écrites sur quatre temps : seule leur fin tombe sur un temps.

## Musique de fond

Une compilation peut jouer une musique sous toute la video (`compilation.music = { track, volume? }`, absente : aucune). Demande du streamer : forte pendant l'intro, baissee quand ca parle, plus presente sur les passages de pur jeu (kills), ou l'on doit quand meme entendre le streamer et les bruits forts du jeu.

- **Catalogue** (`frontend/src/lib/music/catalogue.json`, copie dans `api/public/musics` par `scripts/sync-remotion.mjs`) : pour chaque piste son nom, son auteur, son genre, les types de video auxquels elle va (`kinds` parmi drole, skill, suspense, pose, best-of), ce qu'elle est en une phrase pour l'IA (`about`), et trois mesures (`scripts/make-musics.py --measure`) : tempo, niveau enregistre (`lufs`), endroit ou elle bat son plein (`start` : la video la demarre la). Les descriptions affichees sont dans les fichiers de langue (`compilation.music.about.<id>`). 20 pistes choisies par Corentin sur Pixabay Music : 13 d'abord (phonk, hip-hop, synthwave, chiptune, lofi), puis 7 pour ce qui manquait (4 de suspense, 2 de comedie, 1 trap). Categories et descriptions tirees de l'ecoute par l'IA (voir plus bas), sans ecoute humaine.
- **Fichiers** : `<data dir>/musics/<id>.mp3` d'abord, sinon `api/public/musics/<id>.mp3` (mis la par `scripts/make-musics.py <dossier>`, 128 kb/s, 41 Mo en tout ; `--only <ids>` pour ne traiter que certaines pistes). Une piste dont le fichier manque n'est pas proposee (`GET /api/musics` dit lesquelles sont la). Les 20 mp3 sont dans le depot, donc dans l'installeur : son ami n'a rien a deposer nulle part (decision de Corentin le 15/11/2026, prevenu que le depot est public et que la licence Pixabay interdit de redistribuer les pistes telles quelles) ; `CREDITS.md` dit d'ou elles viennent. Le catalogue livre est relu quand son fichier change (pistes ajoutees pendant que l'app tourne, en dev).
- **Niveau** (`frontend/src/lib/music/mix.ts`) : la piste est d'abord ramenee au niveau du son de la video (-14 LUFS), puis multipliee par une courbe (`curve.ts`, copie cote API) : 0,7 pendant l'intro, 0,09 sous un passage ou l'on parle (environ 20 dB sous la voix), 0,3 sous un passage de jeu, entre les deux selon la part du passage ou quelqu'un parle (`speechShare`, mots dates du clip : parle a partir de 45 %, jeu sous 12 %), pentes de 0,4 s a cheval sur les coupes, fondu d'1 s a la fin. Sans intro, la musique n'est pas la des la premiere image : elle monte en une demi-seconde au niveau du premier passage (bas s'il parle, plus present si c'est du jeu) ; avec ou sans intro, un passage joue au meme niveau. Le calcul est commun aux compilations et aux clips classiques (`lib/music/sound.ts`). « Presence » (discrete, normale, forte) multiplie le tout.
- **Apercu** : le lecteur joue la piste (`<Audio loop>`, depuis `start`) avec cette courbe. Les clips y jouent tels quels alors que l'export monte leur son a -14 LUFS : la musique (et le bruitage de l'intro) est donc baissee d'autant dans l'apercu, d'apres le niveau mesure des clips du live (`GET /api/jobs/:id/loudness`, garde dans `_loudness.json`), pour que l'equilibre entendu soit celui de l'export.
- **Export** : le moteur de rendu ne joue pas la musique. Elle est mixee par ffmpeg apres la mise a niveau (`sound_level.levelArgs`, `music`) : lue en boucle depuis `start`, courbe ecrite en expression (`curveGain`), limiteur au pic autorise. Une piste qui reprend au debut perd son horloge : on lui en redonne une (`asetpts`), sinon son niveau restait fige.
- Mesure sur un vrai export (compilation de 14 passages parles, intro Impact, Drift Phonk) : -14,0 LUFS ; musique seule a -17,9 dB pendant l'intro, -35,5 dB sous les passages (voix entre -16 et -21 dB au meme moment), eteinte a la fin ; duree inchangee.
- **Preferences (DA)** : carte « Musique et intro » de Ma chaine (`SoundPrefs.tsx`) : une musique favorite par type de video (`brand_kit.musics` : type -> piste, la liste envoyee est la liste entiere) et l'intro preferee (`brand_kit.intro`). Une nouvelle compilation s'ouvre avec l'intro preferee (`compilations_controller.store`) ; les favorites sont marquees d'une etoile dans le selecteur de musique et servent de point de depart a l'IA.
- **Choix par l'IA** (`looks.choose_sound`, worker ; `POST /api/jobs/:id/sound` ; bouton « Musique et intro par l'IA ») : un appel texte a GPT-6 Luna (moins d'un centime) qui recoit ce qu'est la video (titre, parties, duree, ce qui se dit dans une quinzaine de passages repartis), ce que le streamer a demande, les pistes presentes sur la machine avec ce a quoi elles servent (les favorites de la DA marquees pour leur type), les 11 intros et l'intro preferee. Il rend le type de video (drole, skill, suspense, pose, best-of), une piste ou aucune, une intro ou aucune, et pourquoi (affiche sous le bouton). Consigne : la favorite du type quand il y en a une ; une intro seulement si elle merite ses deux secondes (compilation titree d'au moins 30 s), jamais pour un moment seul ; ce que le streamer a demande passe d'abord. Lance tout seul apres « Decrire la video » (avec la description) et apres un changement demande dans le fil qui parle de musique ou d'intro. Ce que le streamer avait regle reste (presence de la musique, titre de l'intro). Essaye avec le vrai modele sur la compilation de test (15/11/2026, 0,0003 $ l'appel) : rien demande -> video drole, Pixel Chiptune, intro Stickers ; « une musique qui tabasse et une intro stylee » -> Drift Phonk, intro Vitesse ; « pas de musique, pas d'intro » -> aucune des deux.
- **Ouverture choisie par l'IA** (`looks.choose_sound`, point 3 de sa consigne) : elle dit d'abord comment la video s'ouvre, `opening` : rien, une intro classique ou le hook (le hook quand la video mene a quelque chose qui merite d'etre annonce et qu'un passage ferait un bon apercu ; un jingle pour un best-of ou une serie de moments au titre qui vaut d'etre lu, 30 s ou plus ; rien pour un moment seul), puis les graphismes. Si le streamer prefere le hook (kit), c'est dit. Essai avec le vrai modele (15/11/2026, 2 appels a 0,0006 $, video « Calme… jusqu'a ce que ca derape ») : hook, graphisme Vitesse, passage 12 (« La c'est la merde Tito je suis desole », 6,7 s), coupe nette, les deux fois.
- **Graphismes choisis par l'IA** : elle rend les trois qui vont le mieux a la video, la meilleure d'abord, chacune avec sa raison ; l'app choisit parmi elles (`looks.pick_intro`) : la preferee du streamer si elle en fait partie, sinon la meilleure que l'IA n'a pas deja donnee a ses trois dernieres videos, et si toutes l'ont ete, celle donnee il y a le plus longtemps. Jamais hors des trois : la variete passe apres la pertinence. `intro.by = "ai"` marque une intro choisie par l'IA (posee par `applySound`, retiree quand le streamer prend un autre style) : seules celles-la comptent comme deja donnees. Une intro que le streamer met lui-meme, meme a chaque fois, est son gout et n'est jamais ecartee (remarque de Corentin). Avant, la fiche de Stickers etait la seule a dire « pour les videos droles » : sur une chaine dont les lives sont presque tous classes droles, 5 videos droles sur 5 s'ouvraient dessus (journal d'une soiree d'essais), et l'intro preferee passait apres. Les fiches disent maintenant l'allure et l'energie de chaque intro, plusieurs conviennent a une video drole, et l'IA nomme une intro comme l'app l'affiche (`INTRO_NAMES`, tenu egal aux fichiers de langue par un test : elle disait « Breaking news » a qui lit « Flash info »). Mesure avec le vrai modele (15/11/2026, 8 videos droles d'affilee, 0,004 $) : Flash info, Duel, Impact, Stickers, Flash info, Bandes, Stickers, Flash info. La musique, elle, n'a pas ce garde-fou : sans favorite reglee, la meme piste revient souvent pour le meme genre de video (6 fois sur 8 dans cet essai).
- **Ses propres musiques** (Ma chaine > « Tes musiques ») : le streamer depose un fichier son (`POST /api/musics`), le worker le garde en MP3 dans `<data dir>/musics/<id>.mp3`, le mesure et le fait ecouter (`music_library.py` : deux extraits envoyes a Gemini 3.1 Flash Lite, ~0,001 $) ; l'IA remplit le genre, les types de video et une description, que le streamer corrige (nom, types, description : `PUT /api/musics/:id` ; ce qu'il ecrit est ce que l'IA lit ensuite pour choisir). Sans credits ou si l'ecoute echoue, la piste est ajoutee quand meme, description vide a ecrire. Le catalogue de ses pistes est `<data dir>/musics/catalogue.json` ; tous les ecrans lisent la meme liste (`lib/music/library.ts`, `useMusics`). Les 20 pistes livrees ont ete decrites par la meme ecoute (`scripts/make-musics.py --listen`, 0,009 $ pour les 13 premieres, 0,005 $ pour les 7 suivantes) : elle a corrige trois categories devinees d'apres les titres.
- **Moment fort et montee** (demande de Corentin, 23/11/2026, sur « Money for Nothing » : « ce serait bien que ca monte dans l'intro, et le drop arrive a la fin de l'intro »). `track.start` est le moment fort d'une piste : la ou une video la demarre. Sur ses propres pistes le streamer peut le designer lui-meme (Ma chaine > Tes musiques, champ « Moment fort ») : il tape l'endroit a l'oreille, a la seconde pres, et le worker garde l'attaque la plus proche qui commence quelque chose (`music_library.moment`, 0,75 s de portee : plus fort apres qu'avant, les plus proches d'abord), avec le tempo a partir de la. Le volume ne le trouve pas : le riff de ce morceau (35,1 s) est deux fois moins fort que la montee de batterie qui y mene, et la mesure automatique choisissait 22,8 s, en pleine montee. `track.build` (interrupteur « Monte pendant l'intro ») : dans une video qui s'ouvre sur une intro (jingle, ou moment d'un hook), la piste est lue depuis `start` moins la duree de l'intro (`musicFrom`, meme calcul dans l'app et cote API), donc l'intro joue ce qui mene au moment fort et il tombe sur la premiere image de la video. La musique reste alors devant le temps qu'il s'entende (`DROP` dans `mix.ts` : 0,45 s au niveau de l'intro, puis 0,9 s pour redescendre sous le passage) au lieu de baisser juste avant la coupe. Sans intro, ou si le moment est trop pres du debut de la piste : rien ne change. Essai reel (instance jetable, vrai fichier) : « 35 » tape dans le champ -> 35,1 s et 134,66 bpm ; apercu fabrique hors de l'app (intro Sunset de 4 temps = 1,78 s) : le riff entre a 1,78 s. Export reel (23/11/2026, instance jetable, clip synthetique de 24 s, intro Sunset, mise en page GTA) : 25,9 s, -14,4 LUFS, et le son de l'export est celui de la piste lue depuis 33,32 s a 10 ms pres (correlation avec le fichier) : le riff tombe sur la premiere image de la video. Limites : le riff, plus faible que la moyenne du morceau, passe vite sous la voix (la piste est mise a niveau sur son ensemble) ; pas de detection automatique d'une montee, ni de reglage pour les pistes livrees.
- Pas fait : baisse mot par mot (le niveau est fixe par passage).

## Médiathèque : des vidéos à soi comme passages

Demande de Corentin (24/11/2026) : « un genre de médiathèque dans lequel il pourrait importer des vidéos courtes, de 10, 20 secondes », à reprendre dans les passages (ou importées directement depuis là), et qui marchent « avec l'IA qui fait le montage, l'enlevage des silences, etc. ».

- **Une vidéo importée** (`media_library.ts`, `<data dir>/media/`) : `<id>.mp4` converti une fois en ce que l'aperçu et le rendu lisent à coup sûr (H.264 et AAC, cadence constante, 1920 au plus sur son grand côté, une piste son même si elle n'en avait pas ; une vidéo de téléphone est remise droite), `<id>.jpg`, `<id>_words.json` une fois écoutée (worker `media_library.py` ; liste vide : personne ne parle), `library.json`. 3 min au plus (le plus long passage), 80 vidéos. mp4, mov, m4v, webm, mkv, avi. Refus dits : pas une vidéo, trop longue, médiathèque pleine.
- **Un passage fait d'une vidéo importée** (`item.media`, jamais avec `job`) : ses heures sont les secondes de la vidéo, de 0 à sa fin. Son clip est le fichier de la médiathèque, lié (lien physique, donc aucune place en plus ; copié là où les liens ne se font pas) sous `piece_<id>.mp4` dans le dossier du live de la vidéo, avec `_meta.json { vod_start: 0, vod_end, settled, media }`, `_probe.json` et ses mots : il se coupe, s'habille et s'exporte comme un autre. `POST /pieces` avec `media` ne demande rien au live (marche donc quand le live a quitté Twitch). Pas de webcam ni de chat du live dessus (`resolveEditEnv`, `chatInClip`) ; ses propres dimensions. Clips libérés puis repris : il revient de la médiathèque, pas du live (`piecesToRestore`). Retirée de la médiathèque, les passages déjà faits gardent leur fichier.
- **Dans Monter** : « Importer une vidéo » dans les passages ouvre la médiathèque à leur place (`MediaLibrary`) : « Ajouter » pose la vidéo entière après le passage ouvert (sinon à la fin de la partie), un fichier choisi ou déposé là entre dans la médiathèque et dans la vidéo d'un coup ; la même peut y être plusieurs fois. Sa ligne montre sa vignette et « Importée » à la place de l'heure du live. Une vidéo verticale prend la mise en page plein cadre (`UPRIGHT_TEMPLATE = "plein"`, visible et modifiable sur le passage) au lieu d'être recadrée dans la case du jeu.
- **Dans Ma chaîne** : carte « Médiathèque » (importer, lire, renommer, retirer).
- **Outils de coupe** : « Couper ici », « Enlever les silences » et les poignées marchent dessus (ses mots viennent de l'écoute à l'import, sinon à la première utilisation) ; « ± 30 s » s'arrête aux bouts du fichier ; « Montage IA » est proposé quand le passage ouvert (ou sous la tête de lecture) est une vidéo importée : l'IA en garde les parties qui valent, qui deviennent des passages à sa place (`aiCutPassage`, même endpoint `suggest-cut`).
- **Quand l'IA touche la vidéo** : « Ajuster à 1 min 30 » ne raccourcit ni ne retire jamais une vidéo importée (`fitToTarget`) ; un changement demandé à l'IA ne les lui montre pas (elle ne lit que des lives) et chacune reste dans sa partie, après le passage qu'elle suivait (`planCurrent`, `revisedSections`) ; le Montage IA d'un clip les laisse en place (`recutVideo`).
- **Assistant** : `get_video` dit ces passages `imported` (un nom, une durée, pas d'heure de live) ; `list_imported_videos` liste la médiathèque ; `add_imported_videos` les fait ajouter par l'app (`add_media`, par id ou par nom, sans accents ni casse ; un nom inconnu est redit avec ce qu'il y a).
- Vérifié à l'écran (24/11/2026, instance jetable `.claude/test-data`, faux live et vidéos fabriquées avec une voix de synthèse) : un .mov vertical de 11,7 s importé en 1,5 s (19 mots datés), ajouté aux passages, joué plein cadre avec ses sous-titres ; « Enlever les silences » → trois passages aux bonnes phrases, tous sur le même fichier (même inode que la médiathèque) ; import par l'écran de Ma chaîne ; export réel de 17,5 s, 1080 × 1920, −14,0 LUFS, passages du live et importés mêlés.
- Limites : **pas essayé avec le vrai modèle** : le Montage IA d'un passage importé (réponse simulée dans la page ; côté serveur, testé jusqu'à l'appel du moteur) et les deux outils de l'assistant (réponses simulées) ; pas essayé dans l'app de bureau empaquetée ni sous Windows (liens physiques, ffmpeg embarqué) ; l'IA qui construit ou change une vidéo ne sait pas qu'elles existent (elle ne peut ni les placer ni les retirer) ; « Redemander » une vidéo décrite les perd ; un passage importé garde le son tel quel (mis à niveau avec toute la vidéo à l'export, pas à part) ; l'éditeur à calques prend la taille du premier passage (une vidéo importée en tête lui donne la sienne) ; pas de dossier ni de recherche dans la médiathèque.

## Une compilation dans l'editeur a calques

L'editeur a calques (`RemotionEditor`) travaille sur un clip : une video, une horloge, un jeu de calques. Une compilation en est plusieurs. « Ouvrir dans l'editeur » la colle donc en un seul clip, que l'editeur ouvre comme n'importe quel autre.

- **Le clip** (`compilation_flat.ts`) : `flat_<compilation>_<signature>.mp4` dans le dossier du live de la compilation. Chaque passage y est coupe a l'image pres (l'image est reencodee : une copie ne peut commencer que sur une image cle), tous amenes a la taille et a la cadence du premier, le son descendu a zero sur 8 ms a chaque raccord. Avec lui, comme pour un clip : `_probe.json`, `_words.json` (les mots de chaque passage deplaces la ou il joue maintenant, ceux coupes en moins) et `_chat.json` (le chat de chaque passage, sur l'horloge du clip ; `chatInClip` le lit quand il existe).
- **La signature** nomme les passages et leurs coupes : une compilation qui n'a pas change redonne le meme fichier (rien n'est refait, et l'editeur retrouve le travail deja fait dessus, garde sous le nom du clip) ; une coupe qui bouge donne un autre fichier, l'ancien est supprime.
- **Les calques** de depart : ceux du modele de la video, construits pour ce clip (`buildAny`), plus le titre de chaque partie la ou son premier passage commence. Ils ne sont ecrits que si l'editeur n'a encore rien pour ce clip.
- **Ce qui ne suit pas** : l'editeur n'a qu'une mise en page pour toute la video. Les transitions et le modele propre a certains passages ne sont pas repris (dit sous le bouton quand la compilation en a) ; la cam est celle du live de la compilation (un passage d'un autre live ou elle est ailleurs sera mal cadre).
- **Export** depuis l'editeur : un export classique (`CuttieVideo`) du clip colle ; la bibliotheque le compte comme un export de la compilation (`flat_<id>_…` comme `comp_<id>.mp4`). Le clip part avec la compilation, et avec les clips quand le projet est libere.
- Mesure (14/11/2026, 14 passages de deux lives, 71,8 s en 1080p 60 images/s) : colle en 15 s sur M1 Max, 47 Mo, image et son de meme longueur, 279 mots recales ; rouvert en 0,1 s ; export depuis l'editeur a -14,1 LUFS.

## Authentification

- App locale mono-utilisateur : les requetes venant de l'app sur cette machine (IP loopback, Host loopback, `Sec-Fetch-Site` same-origin/none) sont connectees automatiquement a l'utilisateur local (`local@cuttie.app`, permission `*`) — pas d'ecran de login. Desactivable avec `CUTTIE_AUTO_LOGIN=false` (cas des tests).
- Auth session cookie AdonisJS conservee (login email/password, Google OAuth) pour le mode non-local
- Fichiers (clips, renders, assets) servis via `/api/storage/*` avec URLs signees HMAC(APP_KEY) a duree limitee (pas de session requise pour `<video>` / Remotion)
- Worker <-> API : header `X-Cuttie-Secret` (secret genere a chaque lancement)
- Le Python worker ne connait pas les users (il fait des UPDATE, jamais de INSERT sur jobs)

## Parcours

- Premier lancement `/bienvenue` (installation sans analyse ni `onboarded` dans settings.json) : chaine Twitch (lives + couleurs du logo), deux cles (verifiees aupres de Groq / OpenRouter), webcam reperee sur le dernier live pendant ce temps.
- Projet en 4 etapes : Analyse (en direct) -> Choisir (garder / passer / trim) -> Monter (7 modeles a la DA de la chaine) -> Exporter.
- Choisir : le chat sur la frise du live (barres, le dixieme le plus actif en blanc vif) et sur celle du clip (un point par message, le texte au survol) ; « + » au survol de la frise du clip = 30 s de plus de ce cote (le clip est re-extrait du live quand la coupe depasse son fichier : mots, cam et vignettes suivent) ; « Pourquoi ce moment » dit d'ou vient un moment (score son + chat, lu par l'IA, demande sur le stream, ajoute a la main).
- Coupe en plusieurs morceaux (Choisir) : « Couper ici » (C) coupe le morceau sous la tete de lecture, « Garder ce passage » ajoute un morceau la ou le clip est coupe (du contexte avant la coupe de l'IA), « × » au survol retire un morceau, « Enlever les silences » retire les blancs de plus d'1,1 s (mots du clip), « Montage IA » demande a l'IA les morceaux a garder (moins d'un centime), Annuler / Ctrl+Z. Les poignees se calent entre deux mots (Alt : librement). La lecture saute les coupes. `selection[clip].segments` (2 morceaux ou plus, secondes du clip) ; `trim` reste l'enveloppe.
- Outils de coupe d'un clip, sur une seule ligne (refonte demandee par Corentin le 16/11/2026 : « plein d'actions, avec aussi un peu de texte, un novice peut s'y perdre ») : d'abord ce qui coupe tout seul, un seul controle pour l'IA (`AiCutButton` : le bouton monte, ce qui y pend dit la duree visee et ouvre son menu : Libre, 30 s, 45 s, 1 min, 1 min 30, et « Revenir a la coupe conseillee » quand le clip est coupe autrement), puis un trait, puis les deux outils a la main (« Couper ici », « Enlever les silences ») et Annuler ; a droite ce que donne la coupe (« Coupe conseillee · 0:37 », ou « 2 morceaux · 1:32 »). Plus de phrases dessous (elles sont dans les infobulles), plus de legende du chat, plus de lien a part pour revenir a la coupe de l'IA. Avant : 4 commandes, 5 pastilles, deux phrases, une legende et un lien.
- Duree visee du Montage IA (`lib/cutTarget.ts`, `live_search.suggest_cut`) : gardee par projet dans le navigateur (`cuttie_cut_target_<job>`). Libre : la consigne dit « 45 a 90 secondes » (c'etait 15 a 45 : « mega court pour un clip a mettre sur les reseaux », Corentin). Avec une duree : « environ N secondes », sans jamais couper une phrase pour tomber pile ; un montage a plus d'un quart de la duree est renvoye une fois au modele et le plus proche des deux est garde (les deux appels sont payes) ; un clip qui tient moins que la duree ne peut donner que ce qu'il a. Quand le clip est plus court que la duree visee, l'app l'allonge d'abord avec le « + 30 s » existant (apres, puis avant, 4 fois au plus ; bord du live : l'autre cote ; live parti : avec ce qu'il y a), puis demande le montage. La coupe conseillee par l'analyse (15 a 45 s, `llm_analyzer`) n'a pas change : la revoir demande un essai paye sur un vrai live. Essai a l'ecran (16/11/2026, instance de test, modele remplace par la commande de dev) : un clip de 1 min 10 avec 1 min 30 visee allonge a 1 min 40 (mots suivis), consigne « about 90 seconds », montage de 2 morceaux pour 1 min 32. Pas essaye avec le vrai modele : a quel point il tient la duree demandee n'est pas mesure.
- Compilations = un mode a part entiere, au meme niveau que les clips : onglet « Compilations » de la barre du haut (toutes, groupees par live avec sa date, filtre par live, « Nouvelle compilation » en choisissant le live) et interrupteur « Clips | Compilations » sur les pages d'un projet (`ModeSwitch`). Une carte par compilation : etat (vide, brouillon, exportee = un export fini de `comp_<id>.mp4`, « modifiee depuis » si enregistree plus d'une minute apres), duree, passages, dupliquer (les clips des passages sont copies : la copie marche meme si le live a quitte Twitch), renommer, supprimer. « Nouvelle » reprend la compilation vide laissee la derniere fois plutot que d'en empiler.
- Compilations proposees par l'IA : apres l'analyse, « N compilations trouvees » sur l'accueil et une pastille a cote de « Compilations » ; chaque idee a sa carte (resume, tags, indice de viralite) et se construit quand on l'ouvre (voir « Compilations proposees par l'IA »).
- Editeur d'une compilation (`/:jobId/compilation?c=<id>`, `?new=1` depuis la bibliotheque, `&build=1` : construire l'idee de l'IA qu'on ouvre) : chercher dans tout le live par mots (dits : transcript du live ; ecrits : chat ; gratuit, immediat, phrases serrees quand le transcript a les mots dates) ou en demandant a l'IA (elle fouille le live avec des outils, ecoute et verifie chaque passage : moins d'un centime, 10 a 30 s, reponse gardee sur disque : la meme question ne se paie qu'une fois par version de l'app, et « Redemander » la fait chercher a nouveau ; ce qu'elle fait s'affiche en direct, sa note dit ce qui correspond vraiment, les passages seulement « proches » sont marques), ajouter les passages a des parties titrees, ou decrire toute la video (« Decrire la video » : l'IA propose parties + passages pour une duree visee, et applique la mise en page demandee : voir « Modele par passage »). Chaque passage a son petit clip `piece_<id>.mp4` decoupe dans le live (segments HLS utiles seulement, depuis le debut du premier, 0,6 a 8 s de marge apres), avec les memes fichiers annexes qu'un clip, puis est recale sur ses mots (voir « Coupes calees sur les mots »). Tout reste modifiable : ordre, coupe de chaque passage, titres, modele, « Ajuster a 1 min 30 ». A la premiere visite, l'ecran s'explique en 4 etapes illustrees avec ses propres elements (chercher, ce que fait l'IA, lire ses reponses, construire la video) ; « Comment ca marche » le rouvre. Vu une fois pour toutes : `guides_seen` dans settings.json (pas dans le navigateur, l'adresse de l'app peut changer).
- Ecran d'une compilation, au centre : la video entiere dans son modele, et dessous le passage ouvert pour regler sa coupe (plus d'onglets « Passage | Video entiere »). Un clic sur un passage de la liste amene la video entiere dessus (elle continue si elle jouait, sinon elle s'arrete sur sa premiere image nette, transition finie) et l'ouvre dessous ; le passage sur lequel est la video est marque dans la liste (barre de la couleur de la chaine) et suit la lecture. Un seul son a la fois : la video entiere fait taire le passage et inversement. La video prend la hauteur que la fenetre lui laisse au-dessus du passage ; « × » ferme le passage et lui rend toute sa hauteur.
- Plusieurs passages a la fois (`CompilationPanel.tsx`) : une case sur chaque vignette (au survol, puis sur toutes des qu'une est cochee), Ctrl / Cmd + clic sur un passage, Maj + clic pour tous jusqu'a celui-la. Une barre flottante dit combien sont coches et propose : monter / descendre ensemble (`moveItems` : ils gardent leur ordre, passent dans la partie voisine au bout de la leur), « Deplacer vers » une partie ou une nouvelle (`placeItems`), leur donner une transition, les retirer. Glisser un passage (ou tous les coches, si celui qu'on attrape l'est) le depose ou le trait l'indique, dans sa partie ou une autre ; un appui qui ne bouge pas de 6 px reste un clic.
- Transitions toutes faites (voir « Transitions ») : une pour toute la video (reglages, sous le modele), et un passage peut arriver autrement (bouton au survol de sa ligne, ou depuis la barre des passages coches) ; ce choix s'affiche entre les deux passages.
- Reglages d'une compilation (« Habillage », `CompilationPanel` : `SettingRow`, `TemplateMenu`) : une seule liste de lignes identiques (Univers, Modele, Titres des parties, Style des titres, Transitions, Intro, Musique), chacune avec son icone, sa valeur et son selecteur au clic ; des passages qui font autrement (leur propre modele, leur propre transition) sont dits sous la ligne avec le moyen de tout remettre pareil. Un seul bouton IA, « Laisser l'IA choisir », lance d'un coup la mise en page des passages et le choix de la musique, de l'intro, de la transition et du moment du hook ; ce qu'elle repond tient en deux lignes sous la liste (un clic pour tout lire). Refonte demandee par Corentin (15/11/2026) : avant, chaque reglage avait son titre, sa phrase d'explication et un bouton d'un genre different, et deux boutons IA suivis chacun d'un paragraphe (« beaucoup de texte, ca fait tres AI slop », « pas clair pourquoi des boutons specifiques a l'intro, d'autres aux transitions »). Essai reel du bouton unique : 10 s, moins d'un centime, transition Glisse, intro Vitesse, musique et un autre modele pour 4 passages sur 12.
- A la fin, deux sorties : « Exporter la compilation », ou « Ouvrir dans l'editeur » (voir « Une compilation dans l'editeur a calques »).
- Conversation sur une video decrite (onglet « Decrire la video », `PlanTalk.tsx`) : une fois la video construite, le streamer continue dans un fil (« ajoute les autres moments ou ils disent calme », « apres ce passage, mets celui ou… », « retire le doublon »). L'IA recoit la description d'origine, la video telle qu'elle est (retouches a la main comprises, chaque passage dit par ses lignes du transcript), les demandes precedentes et la nouvelle ; elle rend toute la video (`live_agent.Searcher.revise`, `live_search.revise_video`, meme endpoint `/plan` avec `request` / `current` / `asks`, jamais mis en cache). Ce qu'elle a garde reste le passage d'avant (son clip, sa coupe, son modele) ; un passage qu'elle rend avec d'autres lignes (« des cuts plus agressifs » : `hit.recut`, compare cote worker aux lignes envoyees) garde son clip et son modele et est recoupe sur ces lignes ; rendu en deux, sa seconde moitie est un nouveau passage ; le reste est nouveau (`revisedSections`). La premiere reponse de l'IA (`compilation.answer` : ce qu'elle a mis dans chaque partie et pourquoi) ouvre le fil, et la construction de la video s'y suit pas a pas comme un changement. Le fil (`compilation.brief`, `asks` avec la reponse et le nombre de passages ajoutes / retires) est garde avec la video. A l'ecran : ce que fait l'IA s'ecrit ligne a ligne pendant qu'elle travaille ; les passages ajoutes arrivent eclaires dans la video et la liste defile jusqu'a eux, ceux qu'elle retire s'en vont barres, les autres glissent a leur place ; la pastille « N passages ajoutes » d'une reponse les rallume. ~0,02 $ et 30 s par demande (mesure sur 3 demandes).
- Montage (plusieurs morceaux dans une video) : composition Remotion `CuttieMontage` (app et rendu). Chaque morceau garde l'horloge de son clip (videos, sous-titres, chat) ; l'accroche, les widgets et les titres de parties tournent une seule fois sur l'horloge de la video. Les exports classiques (un clip, une coupe) passent toujours par `CuttieVideo`.
- Design : verre fonce pose sur du contenu floute (vignettes, frames), une seule couleur d'accent = couleur de la chaine.
- Modele par defaut : choisi dans Ma chaine, carte « Modeles » (une ligne « Modele par defaut » qui ouvre la liste de tous les modeles, les siens et les 7 de Cuttie : `TemplateMenu`), ou par l'etoile dans Monter. Demande de Corentin : il devait ouvrir un projet et aller jusqu'a Monter pour le changer.
- Modeles : les 7 mises en page, chacune sa structure (Empile = cam en bandeau / jeu ; Reaction = visage en grand + jeu en vignette ; Discussion RP = scene du jeu + cam ronde, conversation et chat dessous ; Action = jeu plein ecran + cam ronde ; Cinema = ecran du live entier entre deux bandes, titre au-dessus ; Signature = cartes sur fond floute ; Sans cam) + les modeles perso du streamer (`brand_kit.templates`, v2 = elements : fond, jeu (ou ecran entier), cam, chat, sous-titres, accroche, widgets avec arrivee / depart / animations, ordre des calques) ; `brand_kit.default_template` sert aux nouveaux projets. L'editeur a calques reste le mode avance.
- Zones couvertes par TikTok / Shorts / Reels (1080x1920) : haut y < 200, bas y > 1440, droite x > 930 entre y 760 et 1440. Textes, cam et marque restent hors de ces zones (teste) ; le jeu peut passer dessous, une cam pleine largeur en haut passe sous les onglets.
- Accroche = couverture du clip : visible des la 1re image, s'efface apres 3,5 s (ou a la moitie, ou jamais), posee sur le jeu, jamais sur le visage. Sous-titres : 1 a 5 mots a la fois, le mot prononce grossit (`pop`). Chat : messages du clip en bulles (`chatForClip` retire emotes, commandes, bots, liens ; les noms d'emotes viennent de Twitch au telechargement).
- Widgets du kit, polices et transitions : ecrits dans `frontend/`, copies dans `api/remotion` par `node scripts/sync-remotion.mjs` (verifie par `remotionSync.test.ts`).

## App desktop (Windows)

- Electron autour du mode `npm start` : `scripts/launcher.mjs` lance l'API (node.exe embarque, celui du build : `better-sqlite3`) et le worker, attend que les deux repondent.
- Python n'est pas embarque : `uv.exe` installe Python 3.12 + `backend/uv.lock` (PyTorch CUDA 12.6) au 1er lancement dans `%LOCALAPPDATA%\Cuttie\python-env` ; relance un `uv sync` quand `uv.lock` change. Donnees : `%LOCALAPPDATA%\Cuttie\data`.
- Windows neuf : runtime Visual C++ embarque (`resources/bin/msvc`, `CUTTIE_DLL_DIRS` lu par `backend/worker.py`), certificats de certifi pour urllib (`SSL_CERT_FILE`). Le CSS ne doit pas doubler `backdrop-filter` avec `-webkit-backdrop-filter` (le minifieur ne garderait que le second : plus de flou dans l'app compilee, teste).
- Teste en vrai sur un portable Windows (GTX 1650 Max-Q) : live de 7 h 39 analyse en 2 h (transcription locale ~4,6x temps reel), export Remotion OK, mises a jour 0.1.0 -> 0.1.1 -> 0.1.2 (bouton). `--update-test=<rapport>` rejoue le bouton de mise a jour sans fenetre.
- Mises a jour : `electron-updater` + GitHub Releases (`latest.yml`), pastille dans la TopBar, Parametres > Application ; installation silencieuse apres arret de l'API et du worker.
- Son des exports : chaque export est mesure puis amene a -14 LUFS (pic -1,5 dBTP), le niveau auquel TikTok, Shorts et Reels jouent ; un live est souvent bien en dessous (-26 LUFS mesure) et inegal. `sound_level.ts`, ffmpeg `loudnorm` en deux passes, l'image est copiee (7 s pour 1 min 30) ; un echec laisse l'export tel quel. Dans la meme passe, les raccords d'un montage sont adoucis : le son descend a zero sur 8 ms a chaque coupe et remonte aussi vite (une voix coupee en pleine onde fait un clic).
- Journal : `<data dir>/logs/cuttie.log` (API, worker, app ; une ligne = heure ISO UTC), tourne a 10 Mo (cuttie.1.log, cuttie.2.log : 30 Mo max). Parametres > Aide a distance : export .zip d'une periode (journal, diagnostic, analyses et exports, reglages sans cles), « Supprimer les journaux ». On y trouve la vitesse de chaque morceau de transcription, le bilan de chaque analyse (duree des etapes, estimation contre realite), la vitesse des exports et les erreurs de la page.
- Dates de `jobs` : Lucid ecrit et ne relit que `2026-10-11 09:23:17` (UTC). Un UPDATE brut doit passer par `dbTime()`, jamais `toISOString()` (le modele verrait une date invalide et `job.save()` echouerait ; la migration 1776100000000 a remis au propre les anciennes). La table `renders`, elle, est en ISO.

## Webcam

La position confirmee au premier lancement est un **repere**, pas une regle : la cam peut bouger d'un live a l'autre.
- Chaque analyse relocalise la cam sur ses clips (worker, fin de CLIPPING) -> `facecam.json` v3 : le cadre, et qui est ou sur une image cle toutes les 4 s de chaque clip (PyAV, ~1 s par clip).
- `facecam_resolver.ts` : cam reglee a la main pour ce live (`jobs.facecam`) > repere si meme place (IoU >= 0.5) > position du live sinon (`moved`, signale dans Monter).
- La cam est jugee sur la partie exportee (coupe du streamer, sinon coupe de l'IA) : personne dedans sur plus de la moitie des images (webcam passee en plein ecran, ecran de pause, streamer absent) -> monte sans cam, sauf « afficher quand meme ».
